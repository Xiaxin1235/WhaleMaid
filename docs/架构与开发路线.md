## 0. 调研结论（基于本机 DSH 0.1.7-rc.2 环境）

| 事实 | 来源 | 对 WhaleDot 的影响 |
|---|---|---|
| DSH 是 Cordis 插件体系：插件 = `name` + `inject` + `apply(ctx)`，通过 profile 的 `cordis.patch.yml` 装配，`dsh plugin add` 安装 | `~/dshfind/src/content/lessons/dev/*` | WhaleDot 的“Host 半区”做成标准 DSH 插件包（bundle），不改 DSH 核心 |
| 工具调用流水线：`tools/pre-execute`（允许/拒绝门禁）→ 单调守卫 → `tools/execute` → `tools/post-execute` → `tools/result` | dev/02 课 | F22 权限门禁挂在 `tools/pre-execute`，**只收紧不放宽** |
| 会话事件：`turn/start`、`step/start`、`assistant/message`、`tool/call`、`tool/result`、`turn/end`（completed / error / max-tokens / interrupted / blocked / aborted） | `@linxin666/dsh-pet/src/event-projection.ts` | F02 状态动画直接映射这些结构化事件 |
| 外部插件可以通过 `ctx.typertGateway`（`@deepseek-ai/dsh-api-gateway`）调用 `session.create / rename / prompt / page / follow / projections`，并用 `ctx.commands.execute(sessionId, '/permission <preset>')` 钉住权限 | `@linxin666/dsh-client-ui-task-board/src/host-runner.ts`（Apache-2.0） | **DSH Bridge 的执行通道**：每个 Autopilot 任务 = 一个钉住工作区与权限的 DSH 会话 |
| 权限预设：`read-only` / `workspace-write` / `danger-full-access` | task-board `src/core/tasks.ts` | 分析任务用 `read-only`，修改任务用 `workspace-write`，**WhaleDot 永不自动使用 `danger-full-access`** |
| `dsh-goal` + `dsh-goal-round-driver` 是“单会话单目标”续跑；`dsh-schedule` 是会话内提醒 | 官方包 README | 可用于提醒；但 Autopilot 需要跨会话、多任务依赖、独立验收，所以自建任务账本 |
| 已有 `@linxin666/dsh-pet`：在 **Web UI 页面内**浮动的宠物，pet manifest v2（`pet.json` + spritesheet，9 条轨道） | 本机 profile | WhaleDot 做**真正的桌面透明窗口**；角色包**兼容 manifest v2**，用户可直接导入已有角色 |
| 本机：Node 24.18、pnpm 11、Git 2.55、Windows 11 | 本机 | Node 24 自带 `node:sqlite`，持久化无需原生依赖 |

## 1. 总体架构

```
┌──────────────────────── DSH Host 进程（Node） ────────────────────────┐
│  dsh-whaledot（Cordis 插件包，Host 半区）                              │
│   ├─ DshBridge        订阅会话事件；通过 gateway 创建/驱动会话         │
│   ├─ ToolGate         tools/pre-execute 门禁（只拒绝，不放行越权）     │
│   ├─ Store            node:sqlite，~/.dsh/whaledot/whaledot.db        │
│   ├─ Autopilot        调度器 + 任务状态机 + 循环控制（调用 core）      │
│   ├─ Verifier         独立验收：宿主自己跑验收命令，不信模型自述       │
│   ├─ Notifier         分级/聚合/去重/免打扰                            │
│   └─ DesktopApi       127.0.0.1 随机端口 WebSocket + token             │
└──────────────────────────────────▲─────────────────────────────────────┘
                                   │ JSON 消息（@whaledot/protocol 定义）
┌──────────────────────────────────┴─────────────────────────────────────┐
│  WhaleDot Desktop（Electron，独立进程）                                │
│   ├─ PetWindow     透明置顶无边框、拖动/吸附/鼠标穿透、sprite 渲染     │
│   ├─ BubbleWindow  气泡：通知、2–4 个智能选项、快捷输入                │
│   ├─ Tray          托盘：暂停自主执行、勿扰、低资源模式、退出          │
│   └─ PackLoader    角色包（兼容 dsh-pet manifest v2）                   │
└────────────────────────────────────────────────────────────────────────┘

@whaledot/core     纯 TypeScript 领域层：类型、状态机、策略、验收判定、调度决策。
                   不依赖 DSH、不依赖 Electron、不做 IO → 100% 单元测试覆盖关键路径。
@whaledot/protocol Host ↔ Desktop 的消息契约（zod schema + 版本号）。
```

### 关键原则（写进每个提示词）

1. **大脑在 core，手脚在 host**。所有“能不能继续 / 是否越权 / 是否通过”的判断都是 core 里的纯函数，可测试、可复现。
2. **模型只产生“提议”，从不直接产生“动作”**。模型输出（目标草案、下一步建议、智能回复）都要经过 schema 校验 + 策略检查，转换成 `ActionIntent` 后才可能执行。
3. **验收者 ≠ 执行者**。执行在 DSH 会话里；验收由 Host 在工作区里**确定性地**运行用户确认过的命令并采集证据。
4. **授权只能由用户在 Desktop UI 里扩大**。任何来自模型、文件、网页、工具输出的内容都不能修改 `AuthorizationScope`。
5. **未知 ≠ 成功，未知 ≠ 失败**。`UNKNOWN` 必须先核对外部状态，禁止盲目重试。
6. **插件异常不得拖垮 DSH**：所有 `apply` 内部异常捕获并降级，Desktop 断线不影响 Host。

## 2. 仓库结构

```
WhaleDot/
├─ package.json / pnpm-workspace.yaml / tsconfig.base.json / vitest.workspace.ts
├─ packages/
│  ├─ core/        @whaledot/core
│  ├─ protocol/    @whaledot/protocol
│  └─ host/        dsh-whaledot   ← DSH 插件包（含 cordis.patch.yml）
├─ apps/
│  └─ desktop/     @whaledot/desktop（Electron + Vite + TypeScript，渲染层不用框架或用 Preact）
├─ packs/
│  └─ placeholder-whale/   自制占位角色（CC0），保证发行包无授权不明素材
├─ docs/
└─ prompts/        给 GPT 的实现提示词（本目录）
```

技术选型：

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript strict，ESM | 与 DSH 一致 |
| 包管理 | pnpm workspace | 与 DSH 一致 |
| 测试 | vitest | 与 DSH 插件生态一致 |
| 校验 | zod | 协议与模型输出的结构化校验 |
| 存储 | `node:sqlite`（Node 24 内置） | 无原生编译依赖；WAL + 事务 |
| 桌面 | Electron | Windows 透明窗口 + `setIgnoreMouseEvents(…, {forward:true})` 鼠标穿透方案最成熟；后续可评估 Tauri |
| 进程通信 | `ws` WebSocket，仅监听 127.0.0.1，连接需 token | Desktop 是独立进程；token 写入 `~/.dsh/whaledot/connection.json` |
| Git 操作 | 调用系统 `git`（execFile，参数数组，不拼 shell 字符串） | worktree 隔离、检查点提交 |

## 3. 核心数据模型（core 中定义，host 持久化）

```
ProjectGoal        id, title, objective, expectedOutcome, projectRoot, acceptance[], stopConditions,
                   mode('suggest'|'autonomous'|'high'), status, scopeId, createdAt, confirmedAt, version
AuthorizationScope id, goalId, allowedPaths[], protectedPaths[], allowedActions[], forbiddenActions[],
                   verifyCommands[] (用户确认过的精确命令), limits{maxFixRounds=2, maxStallRounds=3,
                   maxRunsPerDay, maxRunMinutes, maxChangedFiles}, permissionPreset('read-only'|'workspace-write'),
                   status('active'|'revoked'), grantedAt, revokedAt, hash
Task               id, goalId, key(稳定去重键), title, kind('analyze'|'edit'|'test'|'doc'|'research'),
                   dependsOn[], state(见状态机), acceptance[], attempts, createdBy('user'|'planner'), version
Run                run_id, taskId, sessionId, worktreePath, baseCommit, startedAt, endedAt, outcome
Attempt            attempt_id, runId, n, …
Checkpoint         id, goalId, taskId, commit, kind, createdAt
Evidence           id, runId, kind('test-report'|'diff'|'file'|'metric'|'log'), path/hash, summary, verdict
MemoryRecord       id, scope('user'|'project'), content, type('fact'|'preference'|'inference'|'external'),
                   source, evidenceRef, valid, version, privacy
Notification       id, kind('progress'|'decision'|'blocked'|'info'), priority, dedupeKey, goalId, taskId,
                   createdAt, deliveredAt, snoozedUntil, readAt
Suggestion         id, notificationId, label(显示文字), intent(ActionIntent), riskLevel, expiresAt,
                   bindTo{goalId, taskId, taskVersion, sessionId}, consumedAt
StateTransition    id, entity, entityId, from, to, at, source, reason, runId
```

任务状态机：`PENDING → READY → RUNNING → VERIFYING → SUCCEEDED`，
分支：`WAITING_APPROVAL / BLOCKED / FAILED / UNKNOWN / PAUSED / CANCELLED`。
所有合法迁移写成一张表，非法迁移抛错；每次迁移写 `StateTransition`。

验收结论：`PASS / FAIL / INSUFFICIENT_EVIDENCE / NOT_SCORABLE / UNKNOWN`。

## 4. Autopilot 一轮（规划书 6.4 的工程化）

```
tick(goalId):
  1 加锁（同项目写任务 = 1）
  2 读取 goal + scope + 最新状态；scope 撤销/目标暂停 → 结束
  3 core.selectNextTask()：依赖已 SUCCEEDED、未超预算、未停滞
       └ 无任务 → core 判断：需要 planner？→ 用 read-only 会话请模型提议下一批任务（JSON），
                  经 core.validateProposedTasks（范围守卫）后写入 PENDING；否则发“决策通知”
  4 core.preflight()：权限/工作区干净/依赖/外部状态
  5 Host 创建 worktree + 基线提交 → DshBridge.launch(会话, cwd=worktree, permission=scope.preset)
  6 监听 turn/end，收集轨迹索引、diff、改动文件
  7 Verifier 在 worktree 运行 scope.verifyCommands → Evidence → core.judge()
  8 core.decideNext()：继续 / 修复(≤2) / 暂停 / 请求决策 / 停止；写状态 + 检查点
  9 Notifier 按需通知；释放锁；按触发器安排下一次 tick
```

**合入用户分支永远需要用户确认**（默认）；Autopilot 只在自己的 `whaledot/<goal>` 分支上提交检查点。

## 6. 协作流程（你 + GPT + 我）

1. 你把 `prompts/00-通用上下文.md` + 某个任务提示词 **一起** 发给 GPT（推荐 Codex 这类能直接读写仓库的形态，让它能读本机 DSH 的 `.d.ts`）。
2. GPT 实现完成后，按提示词末尾的“回报格式”给出总结。
3. 你回到这里说“P0x 完成了”，我会：读代码 → 跑测试 → 做代码审查 → 给出修正提示词或下一个提示词。
4. 每个提示词完成后提交一次 git（提示词里已要求 GPT 不要 push）。
