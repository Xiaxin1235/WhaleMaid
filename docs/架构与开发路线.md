## 0. 调研结论（基于本机 DSH 0.1.7-rc.2 环境与社区插件）

| 事实 | 来源 | 对 WhaleDot 的影响 |
|---|---|---|
| DSH 是 Cordis 插件体系：插件 = `name` + `inject` + `apply(ctx)`，通过 profile 的 `cordis.patch.yml` 装配，`dsh plugin add` 安装 | `~/dshfind/src/content/lessons/dev/*` | WhaleDot 做成标准 DSH 插件包（bundle），不改 DSH 核心 |
| 一个插件包可以同时有 host 半区（Node）与 client 半区（Web UI 页面/面板） | `@linxin666/dsh-pet`、`@linxin666/dsh-client-ui-task-board` | WhaleDot 的目标确认、授权管理、进度查看做成 DSH Web UI 里的面板 |
| 工具调用流水线：`tools/pre-execute`（允许/拒绝门禁）→ 单调守卫 → `tools/execute` → `tools/post-execute` → `tools/result` | dev/02 课 | F22 权限门禁挂在 `tools/pre-execute`，**只收紧不放宽** |
| 会话与 Agent 事件：`session/event`（含 `turn/start`、`tool/call`、`tool/result`、`turn/end` 等）、`session/created`、`agent/status`、`agent/assistant-stream` | dsh-pet `src/event-projection.ts`；dsh-coopanion `src/index.ts` | WhaleDot 用它们追踪自己发起的执行（Run） |
| 外部插件可以通过 `ctx.typertGateway` 调用 `session.create / rename / prompt / page / follow / projections`，并用 `ctx.commands.execute(sessionId, '/permission <preset>')` 钉住权限 | task-board `src/host-runner.ts`（Apache-2.0） | **执行通道**：每个 Autopilot 任务 = 一个钉住工作区与权限的 DSH 会话 |
| 权限预设：`read-only` / `workspace-write` / `danger-full-access` | task-board `src/core/tasks.ts` | 分析用 `read-only`，修改用 `workspace-write`，**WhaleDot 永不自动使用 `danger-full-access`** |
| `dsh-goal` + `dsh-goal-round-driver` 是“单会话单目标”续跑；`dsh-schedule` 是会话内提醒 | 官方包 README | Autopilot 需要跨会话、多任务依赖、独立验收，所以自建任务账本；提醒可复用 schedule |
| **`@takboo/dsh-coopanion`**（AGPL-3.0，v0.4.13）：内置 Coopanion 鲸鱼娘的 Electron 桌宠，随 DSH 会话事件切换动作、目标完成时庆祝；小信封收集回复/审批/提问（`userQuestions`）/异常；双击续聊会话；换装与 figure API 2 角色包导入 | github.com/takboo/dsh-coopanion | **桌宠层直接由它提供**。WhaleDot 的执行跑在 DSH 会话里，鲸鱼自动反应；需要用户决定的事走 DSH 原生审批/提问，进入它的小信封 |
| dsh-coopanion 对外只 `ctx.provide('coopanion', PetControls)`（窗口 start/show/hide/stop），**没有**让其他插件推送自定义气泡或选项的接口 | dsh-coopanion `src/controls.ts` | F04 富交互选项气泡需要给上游提 PR（见 §5 的 UP1）；在那之前用 DSH 原生提问 + WhaleDot 面板 |
| dsh-coopanion 要求 DSH Desktop ≥ 0.2.0-rc.2；本机 Desktop 为 **0.2.1-rc.2**（Cordis 4.0.5，含 `dsh-user-questions`、`dsh-user-approval`、`dsh-permission-presets`） | 其 README；本机 `DeepSeek Harness.exe` 与 `app.asar` | **WhaleDot 以 Desktop 0.2.1-rc.2 为目标宿主**；npm 全局 CLI 0.1.7-rc.2 已过时，不作为 API 依据 |

## 2. 总体架构

```
┌─────────────────────────────── DSH Host 进程 ───────────────────────────────┐
│ dsh-whaledot（Cordis 插件包）                                                │
│  host 半区                                                                   │
│   ├─ DshBridge     订阅会话/Agent 事件；经 gateway 创建/驱动会话、钉住权限    │
│   ├─ ToolGate      tools/pre-execute：WhaleDot 会话的越权调用一律拒绝         │
│   ├─ Store         node:sqlite → ~/.dsh/whaledot/whaledot.db                 │
│   ├─ Autopilot     调度器 + 任务状态机 + 循环控制（决策全部调用 core）        │
│   ├─ Verifier      独立验收：宿主在 worktree 里确定性运行用户确认的命令       │
│   ├─ Notifier      决定何时打扰用户；投递到 DSH 原生审批/提问或面板           │
│   └─ PanelApi      给 client 半区的 HTTP/RPC 路由（沿用 DSH webServer 机制）  │
│  client 半区（DSH Web UI 面板）                                              │
│   └─ 目标列表 / 目标确认与授权 / 任务进度 / 证据 / 暂停-恢复-撤销授权        │
└───────────────┬──────────────────────────────────────────────────────────────┘
                │ 仅通过 DSH 公开服务与事件，无直接代码依赖
┌───────────────┴──────────────────┐
│ @takboo/dsh-coopanion（可选）     │  鲸鱼桌宠：对 WhaleDot 发起的会话自动做动作；
│                                   │  WhaleDot 的提问/审批出现在小信封里
└───────────────────────────────────┘

@whaledot/core  纯 TypeScript 领域层：类型、状态机、策略、验收判定、调度决策、通知策略。
                不依赖 DSH、不做 IO → 关键路径 100% 单元测试。
```

### 关键原则（写进每个提示词）

1. **大脑在 core，手脚在 host**。“能不能继续 / 是否越权 / 是否通过 / 要不要打扰用户”都是 core 里的纯函数。
2. **模型只产生“提议”，从不直接产生“动作”**。模型输出都要经过 schema 校验 + 策略检查，转换成 `ActionIntent` 后才可能执行。
3. **验收者 ≠ 执行者**。执行在 DSH 会话里；验收由 Host 在工作区里确定性运行命令并采集证据。
4. **授权只能由用户在 WhaleDot 面板里扩大**。来自模型、文件、网页、工具输出、会话内回答的内容都不能修改 `AuthorizationScope`。会话内提问只用于“在已授权范围内的选择”。
5. **未知 ≠ 成功，未知 ≠ 失败**。`UNKNOWN` 必须先核对外部状态，禁止盲目重试。
6. **插件异常不得拖垮 DSH**：所有 `apply` 内部异常捕获并降级。
7. **与 dsh-coopanion 零耦合**：不 import 它、不读它的文件；只依赖 DSH 公开服务。它没装时 WhaleDot 功能完整（只是没有鲸鱼）。
8. **许可证**：WhaleDot 代码 MIT。不复制 dsh-coopanion / Coopanion（AGPL）的代码与素材进本仓库；给上游的改动以 PR 形式提交到上游仓库。

## 3. 仓库结构

```
WhaleDot/
├─ package.json / pnpm-workspace.yaml / tsconfig.base.json / vitest 配置
├─ packages/
│  ├─ core/        @whaledot/core
│  └─ host/        dsh-whaledot   ← DSH 插件包（cordis.patch.yml；src/ 为 host 半区，src/client/ 为 Web UI 半区）
├─ docs/           架构、DSH API 查证笔记（P02 产出）
└─ prompts/        给 GPT 的实现提示词
```

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript strict，ESM | 与 DSH 一致 |
| 包管理 | pnpm workspace | 与 DSH 一致 |
| 测试 | vitest | 与 DSH 插件生态一致 |
| 校验 | zod（core）；插件 Config 用 `@deepseek-ai/schemastery` | 模型输出结构化校验；DSH 配置规范 |
| 存储 | `node:sqlite`（Node 24 内置） | 无原生编译依赖；WAL + 事务 |
| 面板 | 按 DSH client 半区规范（参考 task-board / dsh-pet 的 `src/client`） | 不另起前端框架，遵循宿主 |
| Git 操作 | 系统 `git`（execFile，参数数组） | worktree 隔离、检查点提交 |

## 4. 核心数据模型（core 中定义，host 持久化）

```
ProjectGoal        id, title, objective, expectedOutcome, projectRoot, acceptance[], stopConditions,
                   mode('suggest'|'autonomous'|'high'), status, scopeId, createdAt, confirmedAt, version
AuthorizationScope id, goalId, allowedPaths[], protectedPaths[], allowedActions[], forbiddenActions[],
                   verifyCommands[] (用户确认过的精确命令), limits{maxFixRounds=2, maxStallRounds=3,
                   maxRunsPerDay, maxRunMinutes, maxChangedFiles}, permissionPreset('read-only'|'workspace-write'),
                   status('active'|'revoked'), grantedAt, revokedAt, hash
Task               id, goalId, key(稳定去重键), title, kind('analyze'|'edit'|'test'|'doc'|'research'),
                   dependsOn[], state(见状态机), acceptance[], attempts, createdBy('user'|'planner'), version
Run                run_id, taskId, sessionId, worktreePath, baseCommit, startedAt, endedAt, outcome
Attempt            attempt_id, runId, n, …
Checkpoint         id, goalId, taskId, commit, kind, createdAt
Evidence           id, runId, kind('test-report'|'diff'|'file'|'metric'|'log'), path/hash, summary, verdict
MemoryRecord       id, scope('user'|'project'), content, type('fact'|'preference'|'inference'|'external'),
                   source, evidenceRef, valid, version, privacy
Notification       id, kind('progress'|'decision'|'blocked'|'info'), priority, dedupeKey, goalId, taskId,
                   channel('dsh-question'|'panel'|'system'), createdAt, deliveredAt, snoozedUntil, readAt
Suggestion         id, notificationId, label(显示文字), intent(ActionIntent), riskLevel, expiresAt,
                   bindTo{goalId, taskId, taskVersion, sessionId}, consumedAt
StateTransition    id, entity, entityId, from, to, at, source, reason, runId
```

任务状态机：`PENDING → READY → RUNNING → VERIFYING → SUCCEEDED`，
分支：`WAITING_APPROVAL / BLOCKED / FAILED / UNKNOWN / PAUSED / CANCELLED`。
所有合法迁移写成一张表，非法迁移抛错；每次迁移写 `StateTransition`。

验收结论：`PASS / FAIL / INSUFFICIENT_EVIDENCE / NOT_SCORABLE / UNKNOWN`。

## 5. Autopilot 一轮（规划书 6.4 的工程化）

```
tick(goalId):
  1 加锁（同项目写任务 = 1）
  2 读取 goal + scope + 最新状态；scope 撤销/目标暂停 → 结束
  3 core.selectNextTask()：依赖已 SUCCEEDED、未超预算、未停滞
       └ 无任务 → 需要 planner？→ 用 read-only 会话请模型提议下一批任务（JSON），
                  经 core.validateProposedTasks（范围守卫）后写入 PENDING；否则发“决策通知”
  4 core.preflight()：权限/工作区干净/依赖/外部状态
  5 Host 创建 worktree + 基线提交 → DshBridge.launch(会话, cwd=worktree, permission=scope.preset)
       （鲸鱼此时自动进入思考/执行动作——由 dsh-coopanion 根据会话事件完成）
  6 监听 turn/end，收集轨迹索引、diff、改动文件
  7 Verifier 在 worktree 运行 scope.verifyCommands → Evidence → core.judge()
  8 core.decideNext()：继续 / 修复(≤2) / 暂停 / 请求决策 / 停止；写状态 + 检查点
  9 core.shouldNotify() → Notifier 投递（DSH 原生提问/审批 → 鲸鱼小信封；或仅面板）；释放锁；安排下一次 tick
```

**合入用户分支永远需要用户确认**（默认）；Autopilot 只在自己的 `whaledot/<goal>` 分支上提交检查点。

## 7. 协作流程（你 + GPT + Claude）

1. 你把 `prompts/00-通用上下文.md` + 某个任务提示词 **一起** 发给 GPT（推荐能直接读写仓库的形态，让它能读本机 DSH 的 `.d.ts`）。

3. 你把回报贴给 Claude：读代码 → 跑测试 → 审查 → 给出修正提示词或下一个提示词。
4. 每个提示词完成后提交一次 git（GPT 不 push）。
