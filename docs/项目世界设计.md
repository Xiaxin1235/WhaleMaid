# 项目世界设计（草案，计划 1.6）

> 状态：已实现为 1.6 实验功能，默认关闭。时间回放留到后续版本。验证见 [P27 报告](p27-report.md)。

## 1. 要解决的问题

WhaleMaid 的状态散落在面板、通知中心、简报和桌宠信封里，信息完整，但没有“一眼看懂整体”的地方，也缺少能让人记住的样子。项目世界把所有目标放进大肥鱼打理的一座宅邸里：**每个房间是一个目标，房间里的样子就是这个目标的真实状态**。

## 2. 原则

| 原则           | 含义                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------- |
| 有证据才变化   | 世界里每一处变化都对应真实记录：任务通过独立验收，家具才摆好；没有证据的变化一律不画。               |
| 不是养成游戏   | 没有喂食、打卡、体力；不看它不会有任何损失。                                                         |
| 不新增权限     | 世界只负责“看”和“跳转”：点房间打开目标详情，点信件打开现有决策卡、建议卡，所有操作仍走现有确认通道。 |
| 主角是鲸鱼女仆 | 画风与比心动图、桌宠一致的 Q 版；她是宅邸的女仆，不是背景装饰。                                      |
| 安静、省电     | 面板不可见时停止渲染；静置时降帧；遵守“减少动态效果”；任何时候都有可读的列表视图。                   |

明确不做：3D、时间回放（后续版本）、桌宠窗口小地图、可编辑装修或自由摆放家具、任何奖励或惩罚机制。

| 项目里的事实                           | 宅邸里的样子                                                                                               |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------- |

| 目标名称                               | 房门上的铭牌                                                                                               |
| 验收失败、反复失败、停滞（主动性发现） | 房间变乱：地上有杂物、灰尘飘起；越严重越乱                                                                 |
| 等你拍板的决定                         | 门上插着一封信，铃铛轻轻晃动                                                                               |
| 建议卡                                 | 房门旁软木板上的便签                                                                                       |
| 项目雷达：依赖更新 / CI 失败           | 玄关信箱来了包裹 / 房间的灯忽明忽暗                                                                        |

| 自动推进暂停                           | 窗帘拉上、灯关着                                                                                           |

| 全局暂停                               | 大门关闭，她坐在大厅休息                                                                                   |

### 3.1 房间里的摆件（作者 2026-11-09 确定）

一个大目标是一个房间；它下面的每个任务（各自在自己的工作对话里执行）是房间里的一件**摆件**。摆件不只表示“有没有”，而是连续显示进度，让房间本身就是这个目标的仪表盘：

| 摆件                             | 显示什么                                                                          | 数据来源                            |
| -------------------------------- | --------------------------------------------------------------------------------- | ----------------------------------- |
| 水缸                             | 水位 = 该任务最近一次独立验收的测试通过比例；有执行在跑时冒泡泡；验收失败时水变浑 | 验收记录的通过 / 失败计数、运行状态 |
| 书架                             | 书的数量 = 已完成步骤 / 总步骤                                                    | 任务的步骤或检查点                  |
| 盆栽                             | 高度 = 任务阶段（计划 → 执行 → 验收 → 通过）；长期停滞会蔫                        | 任务状态、停滞计数                  |
| 文件架、工具箱、文件托盘和收纳篮 | 摆件下方的小条反映任务阶段，标记提示失败或停滞                                    | 任务状态、停滞计数                  |
| 台灯 / 蜡烛                      | 亮着 = 这个任务此刻有执行在跑                                                     | 运行状态                            |
| 布偶或纪念摆件                   | 验收通过后出现                                                                    | 任务状态                            |

- 每个任务按其类型或顺序分配一种摆件（例如有可计数测试的任务优先用水缸）。每个房间最多一盆绿植；没有专用摆件的任务优先分配不同的家具。
- 按任务而不是按会话显示：一个任务可能因重试跑过多个会话，按任务显示才稳定。
- 房间有固定的摆件槽位（小房间 4 个、中 6 个、大 8 个）；超过时，把已通过的任务收进房间角落的“收纳柜”，柜子上显示数量，点开是列表。
- 数据缺失时（例如验收没有可计数的测试），摆件显示中性状态，不臆造进度。

“乱”的程度、摆件进度等都由现有表计算，计算放在 core 的纯函数里，输入为记录快照和当前时间。

## 4. 白天与黑夜

- 按本机时间（跟随 DSH 时区设置）：清晨、白天、傍晚、夜晚四段，平滑过渡，只改变光照、窗外天色和灯光。
- 夜里：没有目标在跑时，她回到自己的卧室睡觉；有目标在跑时，那个房间亮着台灯，她坐在椅子上工作。
- 勿扰时段内，宅邸进入夜间的安静状态：铃铛不晃动，信件只显示不动画。

## 5. 画面与交互

- **视角**：2.5D 等距（斜 45° 俯视），玩具屋式剖面——每个房间只画后墙两面，前墙去掉，避免遮挡。
- **楼层分开**（作者确定）：各层之间留出间隙，像分层展开的玩具屋，下层房间不被上层地板遮挡。
- **默认单间大房**（作者 2026-11-10 确定）：进入宅邸先看大肥鱼所在的房间，可直接选房。楼层总览保留每层最多四间房的布局。
- **房间要精致**：墙纸、地毯、窗台、踢脚线、光影等细节由程序按统一风格绘制，摆件是视觉重点。大肥鱼在房间内与工作桌大小相近，拉近视角时保持比例。各房间的单扇门使用相同宽度。
- **项目房间陈设**：桌子靠窗，台灯与文件放在桌面，书架和边柜顺着所在墙面摆放，柜门朝房间。工具和收纳靠边角，门内到桌前留走道。
- **布局**：房间按楼层自动排布，一层最多 4 个房间，目标多了往上加楼层；用户可以把房间“归档”（只是宅邸的显示偏好，不改变目标本身），归档的房间收进“储藏室”列表，随时可以搬回；大厅、厨房、陈列室、她的卧室是固定房间。可以拖动和缩放，有“回到大肥鱼所在处”按钮。
- **和她互动**：点击或悬停大肥鱼，她会做出表情反应（与桌宠的情绪表情一致），只是展示，不触发任何操作。
- **桌宠走进宅邸**（实验开关，默认关）：打开“宅邸”标签时，桌面上的桌宠跳一下后隐藏，同时出现在宅邸里她当前所在的房间；离开标签或关闭面板时，桌宠回到桌面原位。桌宠原本就被用户隐藏时不改变它的状态；多个客户端同时打开宅邸时只隐藏一次、全部离开后才恢复。
- **交互**：悬停显示房间摘要（目标名、进度、待处理事项）；点击房间打开目标详情；点击信件 / 便签打开对应的决策卡 / 建议卡；点击陈列品打开已完成目标的总结。
- **列表视图**：同一份数据的文字版，用于读屏和“减少动态效果”，也是加载失败时的回退。

## 6. 角色与美术素材

### 6.1 大肥鱼：复用 Coopanion 的角色渲染（作者 2026-11-09 确定）

宅邸里的大肥鱼与桌面桌宠是同一个角色、同一套动作，**由 Coopanion 自己绘制**，WhaleMaid 不包含任何角色素材或渲染代码：

- 在 WhaleMaid 配套的 Coopanion fork 中新增一个公开的“舞台”接口（具体形式由实现时查证：客户端服务、可嵌入的组件或带消息协议的页面）。WhaleMaid 提供一块区域并下达指令：位置、朝向（左 / 右翻转）、缩放、动作、表情；角色由 Coopanion 的代码和素材绘制。
- **许可边界**：Coopanion 代码为 AGPL，角色贴图的权利属于原设作者，二者都**不得复制**进 MIT 的 WhaleMaid。两个插件只通过这个接口通信，与现在通过 DSH 公开服务协作的关系相同。
- 角色是正面 Q 版，在等距房间里正面朝外显示，走动时左右翻转。
- 动作映射：

| 宅邸里的动作   | Coopanion 的来源                                                 |
| -------------- | ---------------------------------------------------------------- |
| 站立           | 现有待机动作                                                     |
| 行走           | 现有小跳步加位移；如效果不佳，在 fork 中用现有部件补一个走路循环 |
| 坐在椅子上干活 | 在 fork 中用现有身体部件新增“坐姿”与“工作”动作（不新增贴图）     |
| 睡觉           | 在 fork 中以现有“困倦”动作为基础新增睡姿                         |
| 互动表情       | 现有情绪表情（开心、害羞、惊讶等）                               |

- **回退**：没有安装或没有启用兼容的 Coopanion 时，宅邸里显示一张静态立绘（作者绘制的比心图），状态逻辑不变；面板提示“安装完整版可以看到她在宅邸里活动”。
- 发布顺序：先发布带舞台接口的 Coopanion 新版，WhaleMaid 再在完整包中固定该版本。

等距素材统一为 2:1 等距视角、Q 版画风、透明背景 PNG 或 SVG。

| 素材                                                       | 来源                     | 说明                                                 |
| ---------------------------------------------------------- | ------------------------ | ---------------------------------------------------- |
| 门上的信、铃铛、软木板便签                                 | 作者绘制，或先由程序绘制 | 决定和建议的入口，需要醒目                           |
| 房间外壳（地板、后墙、门、窗）、墙纸、踢脚线、窗帘、地毯   | 程序按统一风格绘制       | 首版只有一种房间，但要精致                           |
| 摆件（水缸、书架、盆栽、台灯、纪念摆件）及其进度变化       | 程序绘制                 | 连续进度由程序控制（水位、书本数量、植物高度、灯光） |

具体清单和尺寸在实现前与作者再确认一次。

## 7. 技术方案

- 放在 WhaleMaid 的客户端代码里（MIT），作为 WhaleMaid 面板的新标签“宅邸”。
- 渲染用 Canvas 2D 自行做等距坐标换算和深度排序；只有查证后确认性能不足时，才考虑引入 2D 渲染库（需检查许可和体积）。不引入 3D 引擎。
- 数据来自现有面板 API 的只读汇总接口（新增一个 `world` 查询，返回房间、家具、状态和事件的结构化快照）；世界本身不写任何业务数据。唯一的写入是宅邸自己的显示偏好（归档了哪些房间、视角位置），存在 WhaleMaid 的设置记录里，不影响目标。
- 性能：面板不可见时停止渲染；没有动画时降到每秒数帧；素材按需加载（同欢迎页的做法）。

## 8. 测试要点

- 状态到画面的映射是纯函数：表驱动测试覆盖每种状态（失败、暂停、撤销、决策、建议、雷达事件、全局暂停、完成）。
- 布局：0、1、4、5、20 个目标时的楼层排布，房间不重叠。
- 白天黑夜：各时段边界和时区。
- 交互：每个可点击元素都打开正确的现有界面，不产生任何新的操作路径。
- 列表视图与画面数据一致；“减少动态效果”时没有动画。

## 9. 已确定（2026-11-09 与作者讨论）

1. “窗口”指目标下的任务：一个任务一件摆件，按任务而不是会话显示。
2. 大肥鱼的动作：站立、行走、坐在椅子上干活、睡觉、与用户互动的表情；复用 Coopanion 的角色渲染（见 6.1），桌宠可以“走进”宅邸。
3. 目标很多时先加楼层；用户可以归档房间，归档的房间进“储藏室”，随时可以搬回。
4. 首版只做一种房间，但要做得精致（墙纸、地板、踢脚线、窗帘、地毯、光影）；按目标类型分主题的房间留到以后。
5. 楼层之间分开，像分层展开的玩具屋。

暂无待讨论项。1.5 完成后据此写 1.6 的实现提示词：分为 Coopanion fork 的舞台接口与新动作、WhaleMaid 的宅邸两部分，届时再与作者确认需要作者绘制的少量物件。
