# WhaleDot 使用说明

创建目标后，在 P07 确认授权表单中逐项核对路径、权限、动作、精确验收命令和预算。默认命令模式为“逐条确认”，保持原有门禁。自动推进需要另外确认当前授权。

## 高权限执行

只有工作区可写的目标可勾选“高权限执行”。勾选后先阅读风险说明并再次确认，最后仍需确认整份授权。普通前台命令可直接运行；删除、发布、安装、上传、动态执行、命令文字中的越界路径等会实时请求单次审批，系统配置类命令始终禁止。审批只有“允许一次”和“拒绝”，不回答就不执行。请打开对应执行会话，在 DSH 会话底部审批卡作答；桌宠是否展示取决于独立桌宠插件。

高权限模式下，任意命令可以读写授权目录以外的文件。例如 `node build.js` 里的脚本做什么，WhaleDot 看不到。路径限制只对文件工具和能识别的命令文字有效。危险操作按命令文字识别，只能尽力而为；脚本内部、编码命令、间接调用里的删除可能识别不出来。

能明确拆解的命令包装器会递归检查，最多展开 8 层；无法拆解的包装参数、动态调用目标、环境变量或主目录路径都会要求单次审批。完全可解析且安全的 `cmd /c` 命令、目录内的字面 PowerShell `-File` 脚本可自动运行；内联动态执行、编码执行和其他 shell 入口仍会要求审批。编码内容不会解码分析，删除类别可能只能识别为动态执行。脚本文件内部、运行时下载或生成的代码、自定义函数/别名，以及程序查找路径被改变后的真实程序行为仍可能不可见；递归检查不能消除这些风险。

主要兜底手段有三个：任务在独立 worktree 里执行；WhaleDot 的检查点和回滚；授权目录以外的危险命令一律询问。这些手段不能为任意脚本提供文件系统隔离，检查点和回滚也不能恢复目录外的任意副作用。

等待审批会占用当前运行名额，算入授权中的每次运行时长上限。超时或中止会撤回审批，迟到的允许无效。拒绝、通道不可用、超时或中止会计入拒绝次数并保存证据，正常结束后由现有独立验收流程决定是否转为需要用户决定；不会把模型总结当作成功。时限中止保留 UNKNOWN，再走现有核对流程。

已有目标通过详情里的“重新确认授权”修改模式。替换授权会变更 hash，关闭自动推进；需要重新确认后才能自动推进。运行中的目标不能重新授权。大肥鱼没有开启或提议此模式的入口。分析、调研仍使用只读逐条确认；独立验收始终只执行已确认的精确验收命令。

目标详情显示当前模式。追溯导出保留每个运行的授权版本和危险审批结果，包括类别、命令哈希、结果与时间，不保存命令完整输出。
