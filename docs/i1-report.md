# I1 主动性引擎实现与验收

面板已提供七种规则发现、逐条证据、分级设置和近七天计数。新生成的每日简报最多收录三条发现，大肥鱼可通过只读工具查询。I1 的实际分级为 L0/L1，发现只写自己的记录。

## 查证与处理

| 来源           | 实际结构与 I1 的处理                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 验收与失败签名 | [验收记录](../packages/core/src/verify/model.ts)以运行 ID 为主键，含 `taskId`、`createdAt`、基线、当前命令结果、判定和决策。[命令结果](../packages/core/src/verify/parse.ts)含命令、退出码、尾部和原日志哈希。[执行器](../packages/host/src/verify/runner.ts)为 stdout/stderr 分别保留最后 32,768 个代码单元，入库尾部最多 8,192 个代码单元，日志文件约束为 2 MiB。原实现未统一脱敏。I1 用既有脱敏函数处理签名输入及新面板证据，发现表只保存引用和归一化哈希。命令及尾部按原记录回读，分别最多展示 500、1,000 个代码单元，伙伴工具只返回结论及引用。 |
| 执行次数与时间 | [迁移](../packages/host/src/store/migrations.ts)保留 `attempts` 表，当前写入链路使用 `runs` 和 `tasks.attempts`。`tasks.attempts` 是修复轮数，无法代替运行次数。[调度快照](../packages/host/src/autopilot/scheduler.ts)按本地日计算目标运行次数。D4 用当天运行次数对比有效授权的 `maxRunsPerDay`，并用单次运行的实际耗时对比该运行的 `maxRunMinutes`，优先使用运行保存的授权快照。现有模型没有目标累计时长额度。                                                                                                                                     |
| 停滞与任务判定 | [目标模型](../packages/core/src/model/goal.ts)保存 `stalled`。[默认限制](../packages/core/src/model/limits.ts)中 `maxStallRounds` 为 3。D2 读有效授权的阈值和目标计数，在正数前兆轮触发。NOT_SCORABLE 是验收结论，D3 统计各任务的最新结论。报告型任务沿用 [验收判定](../packages/core/src/verify/judge.ts)的 analyze/research 分类。                                                                                                                                                                                                                 |
| 决策积压       | [通知模型](../packages/core/src/model/notification.ts)区分创建、实际投递、结算、过期和被替代。D5 以 `deliveredAt` 计时，并检查当前目标能自动推进、没有正在运行的任务，以及决定仍绑定同版本的阻塞任务。调度器可能在 24 小时处轮换卡片，自动过期、无人作答且仍绑定同一阻塞任务的旧卡也可作为证据。                                                                                                                                                                                                                                                     |
| 闲置与遗留     | `state_transitions` 是任务流转表。目标状态时间沿用 [目标仓储](../packages/host/src/store/index.ts)维护的简报状态记录，自动推进开关时间来自 `autopilot_events`。授权有效性由 [ScopeService](../packages/host/src/scope-service.ts)复核。缺少可靠起点时，从 I1 首次观测的时间保守累计。目标模型没有结构化最终报告，也没有 SKIPPED 状态，D7 只认完成目标中的 CANCELLED 任务。                                                                                                                                                                           |
| 简报           | [宿主简报](../packages/host/src/companion/daily-brief.ts)将每天首个非空快照保存在 `companion_recall_state` 的 `daily-brief` 项，最多保留 30 天。面板和首次伙伴对话共用同一正文。[模板](../packages/core/src/companion/daily-brief.ts)为最近发现预留空间，正文上限仍为 1,200 字符。简报开关和发现渠道开关作用于之后生成的快照。                                                                                                                                                                                                                       |
| 存储与面板     | `schema_migrations` 追加 v10，升级前保留 SQLite 备份，历史表和旧迁移原样保留。[目标追溯导出](../packages/host/src/autopilot/trace.ts)附上该目标的发现。数据随原 SQLite 目录保留，沿用既有卸载方式。[面板 API](../packages/host/src/panel-api/index.ts)复用已认证的 owner RPC，设置按插件 fiber 和表单 revision 更新，前端沿用现有面板读取模式。                                                                                                                                                                                                      |

## 行为与后续接口

- [核心检测器](../packages/core/src/initiative/detectors.ts)使用快照和传入时间。得分由严重度、置信度和目标相关度计算，新发现的新颖度为 1。冷却内同键的新颖度为 0，刷新原记录的证据和得分。按创建时间 7 天过期，后续满足规则可产生新记录。
- [宿主引擎](../packages/host/src/initiative/service.ts)启动补做，写入后按受影响目标合并 30 秒，本地跨日补扫两个时间规则。普通批次按目标读取索引后的事实，目标内部会回看该目标历史。每批使用 2 秒协作式截止时间并在目标间让出事件循环。同步 SQLite 查询和单条规则计算以边界检查为准。
- 关闭规则会保留旧记录。删除清除该条记录和对应计数，后续仍按当时证据判定。失败和超时写调试日志。错误注入测试同时运行实际独立验收，确认验收和状态流转照常完成。
- [机会类型和分级函数](../packages/core/src/initiative/model.ts)保留 L2/L3、动作、反馈状态、结算时间、冷却和稍后评分接口。通知类型名 `initiative` 仅作预留，建议卡和询问开关处于占位状态。实际检测只产生 L0/L1 记录。

## 隔离验收

用 `scripts/dev-host.ps1 -Profile whaledot-p02 -UseUiKey -TestHome <专用目录>` 运行桌面版自带的 DSH 0.2.1-rc.3 CLI，浏览器通过已认证的本地 Web 端口 3182 打开面板。两组临时 Git 项目各经过三次真实验收命令，执行回合结束事实由测试夹具提供。命令读取不存在的文件，六次均真实返回退出码 1 和 ENOENT。

| 检查       | 观察结果                                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------ |
| 三次失败   | 第一目标产生一条 L1 repeatedFailure，展开后有三条验收证据，链接进入对应目标详情。                                        |
| 开关持久化 | 面板关闭规则，重启后第一条保留。第二目标三次同类失败暂未产生发现。恢复默认后，第二条出现，计数为 2。                     |
| 删除       | 第一次点击打开确认，确认前列表仍有两条。确认后剩一条。                                                                   |
| 次日简报   | 对同一隔离数据库注入次日时间，实际模板包含「最近发现」及「同一原因反复失败」。测试另核对了同日冻结、得分顺序和最多三条。 |
| 隔离和收尾 | 六次命令由独立验收器执行。模型调用 0 次，通知记录 0 条。测试宿主和浏览器已关闭，3182 已释放。                            |

本机证据目录为 `.dsh-dev/i1-home-1794021512461/evidence/`。其中 `initiative-card.png` 记录卡片三部分，`initiative-zh.png` 记录展开的验收证据，`initiative-restored.png` 记录恢复后的列表与计数。`result.json`、两份验收 JSON 和 `next-day-brief.json` 保存结构化结果。

## 审查修正

- 单个目标在 2 秒检测时限内被打断时，保留在待检测队列，下一批继续，不再等到该目标下次变化或跨日。
- 验收命令因超时被终止（无退出码、判定为 UNKNOWN）时，按“命令 + 超时”计算失败签名，连续三次同样超时也会产生“同一原因反复失败”。
