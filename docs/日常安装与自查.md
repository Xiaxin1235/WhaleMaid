# 日常环境安装与自查指南

适用于本机 **DeepSeek Harness Desktop 0.2.1-rc.3**、日常 profile `desktop`（`C:\Users\xx\.dsh\profiles\desktop`）。

下面的命令已在隔离目录 `.dsh-dev/daily-rehearsal` 里用同版本 CLI 实际演练过：安装、启动加载、卸载都能成功。没有在你的日常 profile 上执行过任何命令。

## 你现在的状态

- 鲸鱼插件已经装在日常 profile 里，用的是**链接**：`link:D:/dsh_plugins/dsh-coopanion`。它直接读取 `D:\dsh_plugins\dsh-coopanion` 里构建好的代码。也就是说，这个仓库里的修改，在重启 Harness 后就会进入你的日常桌宠。
- WhaleDot **还没有安装**到日常 profile。

## 一、准备（约 5 分钟）

1. **完全退出 Harness**：托盘图标右键 → 退出，确认任务管理器里没有 `DeepSeek Harness` 进程。
2. **开一个新的 PowerShell 窗口**。之前设过 `DSH_HOME` 的窗口不要用，否则命令会作用到测试环境上。先确认这个变量为空：

   ```powershell
   $env:DSH_HOME
   ```

   有输出就执行 `Remove-Item Env:DSH_HOME`。

3. **备份日常 profile 的配置**（不含依赖目录）：

   ```powershell
   $p = "$env:USERPROFILE\.dsh\profiles\desktop"
   $b = "$env:USERPROFILE\.dsh\profiles\desktop-backup-before-whaledot-20261025"
   New-Item -ItemType Directory $b | Out-Null
   Copy-Item "$p\package.json","$p\pnpm-lock.yaml","$p\cordis.patch.yml","$p\cordis.yml","$p\pnpm-workspace.yaml" $b
   ```

## 二、构建鲸鱼插件

```powershell
cd D:\dsh_plugins\dsh-coopanion
git status --short
npm run build
```

`git status --short` 应该没有输出。如果有，说明另一个模型正在改这个仓库（比如在做 C11）。等它提交、审查通过后再构建，否则你的日常桌宠会带上没审查过的代码。

## 三、生成 WhaleDot 的固定副本并安装

WhaleDot 不直接链接到仓库，而是复制一份**固定副本**到仓库外面。这样 GPT 以后在仓库里改代码、构建，都不会影响你的日常环境；要更新时再手动重做这一步。

```powershell
cd D:\dsh_plugins\WhaleDot
git status --short
pnpm install
pnpm build
pnpm --filter dsh-whalemaid deploy --legacy --prod --config.package-import-method=copy D:\dsh_plugins\whaledot-daily
```

最后一条命令里的 `--legacy` 不能省，否则 pnpm 11 会拒绝。`--config.package-import-method=copy` 也不能省：不加的话副本会和仓库共用硬链接文件，仓库里一重新构建，日常插件就会被原地改坏。

然后把副本装进日常 profile：

```powershell
$dsh = "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd"
& $dsh plugin --profile desktop add link:D:/dsh_plugins/whaledot-daily
```

检查：

```powershell
(Get-Content "$env:USERPROFILE\.dsh\profiles\desktop\package.json" -Raw | ConvertFrom-Json).dsh.profile.bundles
```

列表里应该同时有 `dsh-whalemaid` 和 `@takboo/dsh-coopanion`。

## 四、启动

从**开始菜单**打开 DeepSeek Harness，不要从上面那个 PowerShell 窗口启动。

WhaleDot 的数据会放在 `C:\Users\xx\.dsh\whaledot`，第一次启动时没有任何目标，是空的。

## 六、以后怎么更新

- **鲸鱼插件**：等新的 C 任务审查通过后，完全退出 Harness，在 `D:\dsh_plugins\dsh-coopanion` 执行 `npm run build`，再从开始菜单启动。
- **WhaleDot**：等新的 P 任务审查通过后，完全退出 Harness，删除 `D:\dsh_plugins\whaledot-daily`，重新执行第三部分的 `pnpm build` 和 `pnpm ... deploy`，再启动。不需要重新执行 `plugin add`。数据在 `C:\Users\xx\.dsh\whaledot`，不受影响。

## 七、出问题时怎么退回

1. 完全退出 Harness。
2. 在没有设置 `DSH_HOME` 的 PowerShell 里执行：

   ```powershell
   $dsh = "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd"
   & $dsh plugin --profile desktop remove dsh-whalemaid
   ```

   这条命令只移除 WhaleDot，鲸鱼插件和你的其他插件不受影响（已在隔离环境演练）。

3. 如果配置还是不对，把第一部分备份的文件复制回 `C:\Users\xx\.dsh\profiles\desktop`。
4. `C:\Users\xx\.dsh\whaledot` 里是 WhaleDot 的数据：目标、记忆、回顾。不想保留就删掉，想保留就留着，下次安装会继续使用。
