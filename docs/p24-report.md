# P24 WhaleMaid 1.4 主动性闭环

建议卡由结构化事实触发。通知中心与桌宠信封共用一张卡及其选项账本。建议卡默认开启，主动询问默认关闭。面板可以关闭渠道、调整间隔和冷却期、恢复按目标静默的提醒，也可以撤销学习调整。

## 查证与实现差异

| 查证点        | 代码行为与处理                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| I1 与升级默认 | 原 `InitiativeService.available()` 强制关闭 `cards` 和 `asks`，类型名只作预留。现在使用[分级](../packages/core/src/initiative/model.ts)与[建议卡账本](../packages/host/src/initiative/cards.ts)。I1 面板修改任一开关时曾把两个置灰开关的 `false` 一并保存。新版通过 Loader 的 `Entry.options.config` 识别完整的 I1 面板快照，将旧占位值按新版默认处理。单独声明的 `cards: false` 和 1.4 面板保存的关闭状态仍生效。                 |
| P21 投递      | [策略](../packages/core/src/notify/policy.ts)、[投递器](../packages/host/src/notify/deliverer.ts)及投递历史改用 `isReliableQuestion`，共享认领、每小时预算、勿扰、静音、退避、重启和代数作废。[决策生命周期](../packages/host/src/notify/decision-lifecycle.ts)继续只管 `decision` 与 `blocked`，任务决策可续期，建议卡过期会关闭并记无回应。实际 DSH 原生承运通道要求省略未提供的选项说明，发送 `description: undefined` 会失败。 |
| 现有动作权限  | [CompanionActions.propose](../packages/host/src/companion/actions.ts)要求伙伴会话所有权及原生确认。`draft-goal` 常规入口会调用模型，本次用固定只读模板保存待审核草案，并复用 [P07 编辑器与授权](../packages/host/src/goal-intake/service.ts)。`goal-pause` 走现有暂停服务，`goal-note` 写既有备注账本。`start-work` 会发送普通会话消息，`autopilot` 和 `global-pause` 会改运行状态，它们均未开放给建议卡。                         |
| 同一张卡      | [路由](../packages/host/src/notify/router.ts)在同一事务内校验选项代数、目标版本及当前授权，并持久认领。认领后，本次建议效果、结算及追溯同事务写入。面板「主动性」按发现链接到同一通知，通知中心直接操作，桌宠只使用 DSH 原生提问。桌宠的查看证据和跳转复用现有 owner 导航通道。                                                                                                                                                    |
| 分级与反馈    | L3 没有额外次数限制，仍受共同通知预算；关闭 L3 时可降到已开启的 L2。默认 L1 的 D3/D6/D7 可在面板手动提高到 L2，仍须达到最低得分。D5 沿用 I1 已实现的 24 小时检测阈值。按最新要求，每张卡只提供一个「稍后」，1 小时后再提醒。                                                                                                                                                                                                       |

## 采纳选项

| 检测器            | 可采纳动作                         |
| ----------------- | ---------------------------------- |
| `repeatedFailure` | 起草只读排查目标，或暂停目标       |
| `stallWarning`    | 添加拆分任务备注，或暂停目标       |
| `noAcceptance`    | 打开目标详情，补充验收仍需面板审核 |
| `budgetBurn`      | 暂停目标，或打开目标详情           |
| `pendingBacklog`  | 打开对应待处理决定                 |
| `idleGoal`        | 暂停并备注明日复查，或备注保持现状 |
| `leftovers`       | 起草后续只读检查目标               |

同目标合并按得分排序，每张卡最多两个采纳选项。固定反馈为稍后、忽略、不再提醒这类事和「这条不准」，另有查看证据。每次采纳绑定原卡、目标和授权版本；采纳本身与采纳后带来的进展分别记账。暂停后是否恢复仍由用户选择。

## 离线评测

| 回放场景                             | 结果                                                           |
| ------------------------------------ | -------------------------------------------------------------- |
| 7 个检测器各自的应触发、不触发与边界 | 21/21，准确率 100%                                             |
| 合并、L2 间隔、L3 通道、7 天冷却边界 | 6 条同目标机会进入同一批，分数降序，边界断言全部通过           |
| 多目标共享每小时额度                 | 6 条候选中投递 4 条，含 1 条决策和 3 条建议，勿扰期间投递 0 条 |
| 10 条已投递的反馈样本                | 采纳 20%，无效打扰 80%，采纳后进展 50%，误触发 10%，模型成本 0 |
| 自动调整                             | L2 降到 L1，最低得分调到 0.4                                   |

[评测脚本](../scripts/eval-initiative.mjs)纳入 CI，固定夹具的触发准确率必须为 100%。统计按检测器对同张卡计一次，稍后再次投递沿用同一张卡。未回应在到期后计入，失效或合并时未选中的附带发现不计为无效打扰。

## 1.5 接入点

[InitiativeService.detectGoal](../packages/host/src/initiative/service.ts)负责组装结构化快照。项目雷达可在这一层加入只读外部变化事实，经纯检测器产出带 `dedupeKey`、证据引用和评分的 `OpportunityCandidate`。结果复用现有分级、合并、授权绑定、投递、反馈和指标。外部变化本身不会成为命令或授权。

## 已知限制

- DSH 原生问题没有已读回执，投递指标记录问题已交给承运服务的尝试，明确失败的首次尝试从指标撤回。小时预算仍计算该次尝试。
- I1 完整面板快照与人工逐字段写出的完全相同 YAML 没有可辨别的来源标记。迁移按 I1 快照处理这种完整形状。
- 发布包和市场仍使用已发布版本。此改动只准备本地 1.4.0。
