## 实现

- 总开关默认关闭。作者在目标详情预览清单并选择来源，确认绑定到预览和当前授权。改授权后需要重新确认订阅。自动联网遵守本地日期和检查间隔。手动检查遵守 GitHub 限流。
- D8 和 D9 复用建议卡与待审核的只读草案。D10 通过询问、建议卡或面板提供继续、暂停、查看改动。查看改动后仍需继续或暂停。D11 的投递渠道只有每日简报。
- SQLite 迁移 12 增加两张雷达表。每来源每目标保留 96 条快照，等待中的冲突证据另外保留到结算。近 7 个本地日的统计使用日汇总。导出的目标追溯含订阅、观察、冲突及用户选项。
- 检测证据存结构化引用和摘要哈希。卡片使用固定文案。手动打开来源摘要时，才额外联网读取并截取最多 600 字符，以纯文本显示。

## 已知限制

- Git 没有记录未提交改动的作者。雷达用工作树、运行、已知检查点及实际放行的写入面归因。能由本次 WhaleMaid 工具写入的路径视为归因不明，允许任意写入的命令会让该次工作树的脏改动无法可靠归因。标记为 partial clone 的仓库跳过本地检查，避免懒取对象。每次最多投影 100 条路径或提交。见 [Git 环境变量](https://git-scm.com/docs/git#Documentation/git.txt-GITALLOWPROTOCOL)。
- `继续` 恢复调度资格。已有的工作树完整性、授权、预算、待处理决定等执行条件仍参与放行。
- 版本范围只能提供声明的基准，精确的弃用检查需要版本固定。依赖范围在确认订阅时固定，清单变化可重新预览。上游没有在注册表元数据公开发布说明时，只能按版本和弃用状态判断。一个来源失败时，当次结果不会产生新建议。
- GitHub 首版检查最近 12 次已完成 CI、最近 20 个新开的开放条目，以及每次最多 3 个 PR 的前 30 个文件。相关性是标题和路径规则。ETag 缓存在当前宿主进程中，重启后重新建立。
