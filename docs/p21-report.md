# P21 决策提问可靠投递

## 查证

| 疑点       | 原有行为及影响                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 一次性投递 | [策略](../packages/core/src/notify/policy.ts)曾对所有已尝试记录统一拦截，除非有更新的提醒时间。[投递器](../packages/host/src/notify/deliverer.ts)在提问服务失败时恢复送达时间，保留尝试时间。会话准备失败则发生在认领之前，只能等下一次扫描。                                                                                                                                                                                                         |
| 系统中止   | 宿主停止、静音或任务版本变化都会使原提问结束。原记录写成通用取消状态，恢复后仍被已尝试规则拦住。勿扰原来只影响新提问。                                                                                                                                                                                                                                                                                                                                |
| 选项截断   | [选项构造](../packages/core/src/notify/suggestions.ts)原来先按固定顺序取前两项，加入改方向后可能把接受挤掉。用户历史只影响所选项的排列。                                                                                                                                                                                                                                                                                                              |
| 24 小时    | [任务通知](../packages/host/src/verify/verify-task.ts)和[目标通知](../packages/host/src/goal-notices.ts)原来都设 24 小时。旧[调度器](../packages/host/src/autopilot/scheduler.ts)扫描时会先结束过期记录，再尝试给仍暂停或阻塞的任务创建决策，或重发目标通知。截止时间与扫描之间存在不可操作的空档，重建还会丢失旧选项身份和已投递状态。任务去重按目标、任务和决策类型匹配，同时要求原记录未处理、未过期且任务版本相同。任务状态不会随通知过期而推进。 |

[inbox](../packages/host/src/notify/inbox-session.ts)使用 DSH 的公开问题服务。选项和自定义文字来自回答批次，空批次或空选项且无自定义文字记为未作答。服务可返回 `NO_PROVIDER` 或 `CALLER_NOT_LIVE`，会话查找失败也可在准备阶段观察到。会话删除后若旧提问返回且原 agent 已消失，记投递失败，下次准备重新检查会话归属并按需重建。桌宠仍能承接时，Harness 客户端离线或「在 Harness 处理」提示本身无法说明用户是否看到问题。公开 API 没有已读或关闭来源。未携带 WhaleMaid 自身中止信号、且没有会话失效证据的 `ASK_ABORTED` 按未作答保守处理，可从面板手动提醒。

[任务写入](../packages/host/src/store/index.ts)对同状态元数据更新和状态迁移都递增版本。事件或验证记录独立追加时可以不改任务版本。P21 用当前授权、最新执行和最近任务状态迁移共同核对决策身份。同一等待状态内的元数据更新可以换代；发生状态迁移、执行替换或目标终结后结束旧决策。已有关闭、作答或退避的状态在安全换代时保留。

[路由](../packages/host/src/notify/router.ts)仍在事务里验证绑定、消费选项、持久认领并写入待结算选择，然后执行。P21 加上投递代数校验。面板和桌宠同时提交时，先认领的一方拥有执行权。

## 选项

| 通知类型或原因                                                                                                                                                                                  | 必选项（只从通知的合法操作中取）                        |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 一般验收，如 `not-scorable`、`insufficient-evidence`、`fix-rounds-exhausted`                                                                                                                    | 接受、重试、可用时撤销后再试                            |
| `verification-unknown`                                                                                                                                                                          | 重新核验、接受                                          |
| `blocked`、`stalled`、`execution-needs-owner`、`execution-stopped`、`execution-preflight-blocked`、`autopilot-disabled`、`reconcile-blocked`、`planner-need-user`，以及不提供接受的其他阻塞决策 | 优先继续目标，其次重试；可用时提供改方向                |
| 剩余名额                                                                                                                                                                                        | 依次考虑稍后提醒、暂停、查看差异和打开面板，总计 2–4 项 |

历史频率只排列已选定的集合。改方向和放弃仍可从面板处理，放弃继续要求面板二次确认。撤销继续核对检查点和授权。选项规则和通知投递均无模型调用。

## 持久化和追溯

- 认领与投递开始记录在同一事务写入，每个目标同时只有一条提问。准备或问题服务失败按 1 分钟、5 分钟、30 分钟、之后每 2 小时重试。所有决策尝试占用每小时预算；系统中止保留原失败次数。重启时恢复持久化的进行中尝试，已有的操作认领继续由路由约束。
- 仍需处理的决策沿用原记录和选择历史。到期时核对授权与任务状态，合法时顺延 24 小时及当前选项的可用期。授权变更或撤销时标明失效，状态或执行变化时标明取代。旧记录缺少版本换代依据时，结束旧卡并由当前任务状态决定是否另建。
- 迁移 11 保留旧通知和选择。明确记录失败的旧决策进入退避；其他旧已尝试记录按送达情况未知处理，留在面板等待主动提醒。
- 通知中心显示投递状态、下次可提问时间和中英文投递历史。投递日志记录通知 ID、代数、事件和有限原因代码。提问正文、用户输入和供应商异常正文留在这条日志之外。
