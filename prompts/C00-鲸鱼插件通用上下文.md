# 【改鲸鱼插件时，每次附在任务提示词前面发给 GPT】dsh-coopanion 本地扩展通用上下文

你在为用户本地扩展社区插件 **dsh-coopanion**（DeepSeek Harness 的鲸鱼娘桌宠）。这是用户自用的修改版；它与 WhaleDot 是两个独立项目。

## 仓库与许可

- 工作目录：`D:\dsh_plugins\dsh-coopanion`（克隆自 https://github.com/takboo/dsh-coopanion ，基于 `v0.4.13`）。
- 许可证 **AGPL-3.0-or-later**；`web/upstream/whale/` 的贴图另有权利声明。保留所有版权与许可声明；新文件头部写 `SPDX-License-Identifier: AGPL-3.0-or-later`。
- **不要**把这里的代码复制进 WhaleDot（`D:\dsh_plugins\WhaleDot`，MIT）。两者只通过 DSH 公开服务协作。
- 工作分支：`whaledot-local`（不存在就从当前 `main` 创建）。本地提交，**不要 push、不要发布 npm、不要改版本号发布**。

## 开始前必读

1. 仓库根目录的 `AGENTS.md` 与 `docs/README.md`，再按任务读取对应契约（回复/收件箱：`docs/notification-contract.md`、`docs/session-chat-contract.md`、`docs/text-readability-contract.md`；角色：`docs/characters.md`）。
2. 结构笔记：`D:\dsh_plugins\WhaleDot\docs\upstream\dsh-coopanion-结构笔记.md`（行号可能已过时，以源码为准）。
3. DSH API 查证：`D:\dsh_plugins\WhaleDot\docs\dsh-api-notes.md` 与参考副本 `D:\dsh_plugins\WhaleDot\.dsh-ref\0.2.1-rc.2\`。**不要臆造 DSH API**，找不到出处就停下说明。

## 工程约定（遵循上游，不要换工具）

- 包管理用 **npm**（`npm ci`），不是 pnpm；Node 24。
- 构建 `npm run build`；测试 `npm test`；改动回复/收件箱/字号/多屏/NPC 的必须加跑 `npm run test:inbox-ui`；原生窗口相关跑 `npm run test:desktop`。
- 产品行为变更要**同步**：实现、测试、`docs/usage.md`（中文）与相关契约文档。
- 新增设置项走插件现有的设置机制（`settings.mutate('dsh-coopanion', ...)` 一类），中英文案进现有 locale 文件。
- 所有新功能默认行为要与 0.4.13 一致或明确更好；可选功能默认关闭。

## 测试环境（重要）

- **不要在用户日常的 DSH profile 中测试。** 使用 WhaleDot 的隔离环境：`D:\dsh_plugins\WhaleDot\scripts\dev-host.ps1`（`DSH_HOME=.dsh-dev`，并已设置 `DSH_PET_TEST_DATA_DIR`，让测试鲸鱼使用独立的数据目录）。
- 原因：dsh-coopanion 默认把 Electron 数据放在 `%APPDATA%\DeepSeek Whale`，**测试鲸鱼与用户日常鲸鱼共用该目录时会互相干扰**（已导致日常鲸鱼消失）。任何手动启动的测试宿主都必须设置 `DSH_PET_TEST_DATA_DIR` 指向 `.dsh-dev` 下的独立目录。
- **禁止在设置了 `DSH_HOME` 的终端里启动 DeepSeek Harness 桌面应用**（包括打开 `dsh://` 链接、运行 `DeepSeek Harness.exe`）：桌面应用是单实例的，它会继承测试用的 `DSH_HOME`，导致用户之后打开的“日常” Harness 实际运行在测试数据上（已发生过一次）。测试只用 `dsh.cmd --profile <测试 profile>` 启动的 Web 界面。测试结束必须停止自己启动的所有宿主与测试鲸鱼进程。
- 在测试 profile 中用 `link:` 安装本地修改版（先移除该 profile 里 npm 版本的 `@takboo/dsh-coopanion`）。
- 桌宠是原生窗口，你无法目视确认时，如实写“未目视确认”，并列出请用户确认的具体现象。

## 验收报告放哪里

- 验收报告、证据清单写到 **WhaleDot 仓库** `D:\dsh_plugins\WhaleDot\docs\coopanion\<任务编号>-report.md`，证据文件放 `D:\dsh_plugins\WhaleDot\.dsh-dev\<任务编号>-evidence\`。
- 报告写完后，在 WhaleDot 根目录执行 `pnpm exec prettier --write <报告路径>`，保证 WhaleDot 的 `pnpm format:check` 通过，再提交到 WhaleDot。
- **不要**把报告或证据提交进 dsh-coopanion 仓库：这些改动将来可能以 PR 提交给原作者，仓库里只保留产品代码、测试与面向用户的文档。
