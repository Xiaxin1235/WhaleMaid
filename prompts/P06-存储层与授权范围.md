## 要做的事

### 1. `packages/host/src/store/`
- 数据库文件：`<dataDir>/whaledot.db`；`PRAGMA journal_mode=WAL`、`foreign_keys=ON`、`busy_timeout=5000`。
- **单写者锁**：同一 `dataDir` 只允许一个宿主进程打开（锁文件 `<dataDir>/whaledot.lock`，写入 pid 与启动时间；发现旧锁时检查 pid 是否仍存活，存活则 WhaleDot 进入只读降级并在面板显示“另一个 DSH 正在使用 WhaleDot 数据”，不得抢锁）。
- **迁移**：`schema_migrations` 表 + 有序迁移数组；启动时在事务内执行；迁移失败则不打开数据库、插件降级、面板显示错误。迁移前自动备份 `whaledot.db` 到 `<dataDir>/backups/`（保留最近 5 份）。
- 表：`goals`、`scopes`、`tasks`、`state_transitions`、`runs`、`attempts`、`checkpoints`、`evidence`、`notifications`、`suggestions`、`kv_settings`。主键用 core 的品牌 ID；业务字段可用 JSON 列，但**读出时必须经 core 的 zod schema 校验**；校验失败的行不让整个读取崩溃——跳过该行、记入 `<dataDir>/debug/host.log`，并在面板状态里计数“损坏记录 N 条”。
- 仓储接口（本任务实现前五个，其余只建表）：`GoalRepo`、`ScopeRepo`、`TaskRepo`、`TransitionRepo`、`RunRepo`。
- **状态迁移事务**：`TaskRepo.transition(taskId, to, meta)` 在一个事务里：读任务 → 调 `core.transition` → `UPDATE tasks ... WHERE id=? AND version=?`（受影响行数为 0 视为 `stale-version`）→ 插入 `state_transitions`。不允许绕过此方法直接改 `tasks.state`。
- 时间与 ID：生产实现 `Clock = Date.now`，`IdGen` 用 `crypto.randomUUID()` 加前缀；测试注入确定性实现。

### 2. 授权范围生命周期 `packages/host/src/scope-service.ts`
- `grant(draft)`：只接受来自**已认证面板 owner** 的调用（P07 的确认界面会调用它；本任务先提供服务与测试，不暴露创建入口）。计算 `hash`（Host 注入 SHA-256），`status: 'active'`，写入。
- **不可变**：授权一旦写入不修改内容。修改授权 = 创建新版本（新 id，`supersedes` 指向旧版），旧版置为 `superseded`（在 core 的 scope status 中新增此状态并更新 schema 与 `checkAction`：非 `active` 一律 deny）。
- `revoke(scopeId)`：立即生效（写 `revoked` + `revokedAt`），并发出 Cordis 事件 `whaledot/scope-revoked`（插件内部事件，P08 用它中止正在运行的会话）。
- `activeScopeFor(goalId)`：读出后重新计算 hash 与存储值比对，不一致视为被篡改 → 当作无授权（deny）并记日志。
- 测试对应规划书验收用例 9：撤销后 `checkAction` 对任何动作返回 deny；篡改 hash 后 deny。
