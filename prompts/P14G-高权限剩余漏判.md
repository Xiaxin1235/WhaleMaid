## 背景

P14F 审查时，用真实的 `checkAction`（trusted 授权、cwd `C:/proj`）另测了 54 条命令。下表的命令仍然直接 `allow`，或者类别标错。只修这些，**不改**授权、审批、审计流程，不改 confirmed 模式。

| 命令                                         | 现在                                 | 应该                                                                          |
| -------------------------------------------- | ------------------------------------ | ----------------------------------------------------------------------------- |
| `forfiles /c "cmd /c del @file"`             | allow                                | ask：`forfiles` 作为包装器，按 `/c` 的内容递归判定，得到 dynamic-execution、delete |
| `rundll32 x.dll,Entry`                       | allow                                | deny：system-configuration                                                    |
| `regsvr32 x.dll`                             | allow                                | deny：system-configuration                                                    |
| `shutdown /s /t 0`                           | allow                                | deny：system-configuration                                                    |
| `Stop-Process -Name explorer -Force`         | allow                                | ask：新类别 `process-control`                                                 |
| `git checkout .`                             | allow                                | ask：repository-delete（会丢弃未提交改动）                                    |
| `git switch -f main`                         | allow                                | ask：repository-delete                                                        |
| `schtasks /create /tn x /tr calc`            | ask / ambiguous-command-path         | deny：system-configuration                                                    |
| `taskkill /f /im explorer.exe`               | ask / ambiguous-command-path         | ask：process-control                                                          |
| `npm uninstall lodash`                       | allow                                | ask：package-install（与安装同类，修改依赖）                                  |
| `del /q /s *.tmp`                            | deny / 保护或歧义路径                | ask：recursive-delete。只有确实命中保护路径或保护名称时才 deny               |
| `Get-ChildItem *.log \| % { Remove-Item $_ }` | deny / 保护或歧义路径                | 同上：没命中保护规则时 ask：delete                                            |

## 实现要点

1. **包装器**
   - `forfiles` 加入包装器表：取 `/c`（或 `-c`）的参数，按现有递归规则判定，深度限制不变。
   - 拆不开时 ask（`unparsed-command`）。
2. **系统类，直接 deny**
   - 新增：`rundll32`、`regsvr32`、`shutdown`、`Restart-Computer`、`Stop-Computer`、`schtasks`（`/create`、`/change`、`/delete`、`/run`）、`Register-ScheduledTask`、`Unregister-ScheduledTask`、`mshta`、`wmic`（带 `process call create`、`delete` 等修改类参数）。
   - `schtasks /query` 只读，allow。
3. **新类别 `process-control` → ask**
   - 包括：`taskkill`、`Stop-Process`/`kill`/`spps`（核对 PowerShell 实际别名后列入）、`tskill`。
   - 结束本任务自己启动的进程也会被问。这是预期行为，写进报告。
4. **repository-delete 补全**
   - 判为 repository-delete 的情况：
     - `git checkout` 后跟 `.`；
     - `git checkout` 带 `-f`/`--force`；
     - `git checkout -- <路径>`；
     - `git switch` 带 `-f`/`--force`/`--discard-changes`；
     - `git restore --worktree`（已有 restore 规则时一并核对）。
   - 切换分支本身（`git switch main`、`git checkout main`）仍然 allow。
5. **package-install 补全**
   - `npm`/`pnpm`/`yarn` 的 `uninstall`、`remove`、`rm`、`un` 子命令判为 package-install。
6. **reason 准确**
   - 现在 `*.tmp`、`$_` 一类参数会被当作“保护或歧义路径”直接 deny。改为：只有通配符确实可能命中 `protectedPaths`/`protectedNames` 时才 deny（沿用现有 `overlap` 判定），否则按真实危险类别 ask。
   - `$_` 这类变量参数归 `unresolved-command-path` 并 ask，不 deny。
   - `schtasks`/`taskkill` 不能再只显示 `ambiguous-command-path`。

## 测试
