## 审查结论

P14 的授权、审批、审计和 stopGoal 修正都通过。问题只在 `inspectTrustedCommand` 的文字识别：审查时用真实的 `checkAction`（trusted 授权、cwd `C:/proj`）跑了 21 条危险命令，18 条直接 `allow`，其余 3 条只是碰巧被 ask（见表后说明）。这些是日常写法，不是刻意绕过，必须拦住。

| 类别                       | 被放行的命令（必须改为 ask 或 deny）                                                                    |
| -------------------------- | ------------------------------------------------------------------------------------------------------- |
| 包装器里的删除工具         | `npx rimraf dist`、`pnpm exec rimraf dist`                                                              |
| PowerShell / cmd 参数简写  | `pwsh -c "Remove-Item a.txt"`、`powershell -Comm "…"`、`cmd /k del a.txt`                               |
| 其他 shell                 | `bash -c "rm a.txt"`、`sh -c "rm a.txt"`、`wsl rm a.txt`                                                |
| 其他动态执行               | `node -p "…"`                                                                                           |
| .NET 静态方法              | `[System.IO.File]::Delete('a.txt')`、`[IO.Directory]::Delete('out', 1)`                                 |
| 变量 / 点号调用            | `$x = "Remove-Item"; & $x a.txt`、`. Remove-Item a.txt`                                                 |

另外：

- `format D: /q`、`robocopy empty out /MIR`、`Start-Process cmd -ArgumentList "/c del a.txt"` 只是碰巧因 `ambiguous-command-path` 被 ask，类别标错。用户在审批卡上看到的原因会误导人。
- `format`、`diskpart` 应归入系统配置，直接 deny。

## 修正原则

识别仍然是“尽力而为”，但方向改为：**看不懂的执行方式一律 ask，而不是放行**。只有能看清“执行的是哪个程序、参数是什么”的命令才可能 allow。

## 实现（只改 core 的识别与对应文案、测试；不改授权、审批、审计流程）

1. **包装器展开**
   - 以下包装器要剥掉，对被包装的命令**递归**用同一套规则判定，并限制递归深度：
     - `npx`、`pnpm exec`、`pnpm dlx`、`npm exec`、`yarn dlx`、`yarn exec`、`bunx`；
     - `cmd /c`、`cmd /k`；
     - `Start-Process` 的 `-FilePath` / `-ArgumentList`；
     - `env`、`call`、`start`。
   - 被包装的是以下删除工具时归为 `delete`：`rimraf`、`del-cli`、`trash`、`trash-cli`、`shx rm`。
   - 包装器后面的内容无法可靠拆解时 → ask（`unparsed-command`）。
2. **嵌套 shell 与动态执行，归为 `dynamic-execution` → ask**
   - PowerShell（`powershell`、`pwsh`）带 `-Command` 的**任意无歧义前缀**：`-c`、`-co`、`-com`、`-comm`…… PowerShell 接受参数前缀，按前缀匹配。
   - PowerShell 带 `-EncodedCommand` 的任意前缀：`-e`、`-en`、`-enc`……
   - PowerShell 带 `-File` 并执行授权目录以外的脚本。
   - `cmd` 带 `/c`、`/k`，大小写不敏感。
   - `bash`、`sh`、`zsh`、`wsl`、`busybox`（带任何参数）。
   - `node` 带 `-e`、`-p`、`--eval`、`--print`；`deno eval`。
   - `python` 带 `-c`；`perl`、`ruby` 带 `-e`。
   - `Invoke-Expression`、`iex`、`Invoke-Command`、`icm`。
   - `Add-Type`。
   - 任何 `[类型]::方法(...)` 形式的 .NET 静态调用。其中方法名为 `Delete`、`Move`、`Replace`、`WriteAll*`、`Copy` 时类别为 `delete` 或 `write-outside-check`，其他为 `dynamic-execution`。
3. **调用目标看不清 → ask（`dynamic-invocation`）**
   - 每段命令的第一个词是变量（以 `$` 开头）、表达式，或者是调用运算符 `&` 或点号 `.` 后面跟变量或字符串，都按此处理。
   - `& "Remove-Item"`、`. Remove-Item` 等可以确定程序名的，取出程序名后照常判定。
4. **删除类补全**
   - `robocopy` 带 `/MIR` 或 `/PURGE` → `delete`。
   - `Clear-Content`、`Clear-Item` → `delete`。
   - `Set-Content`、`Out-File`、重定向 `>` 指向授权目录外 → `outside-command-path`；目录内照常 allow。
   - `Remove-Item` 的别名补全：`rm`、`ri`、`del`、`erase`、`rd`、`rmdir`、`rni`（若存在）。按 PowerShell 实际别名核对并在报告列出。
5. **路径**
   - 以下形式的参数无法静态确定位置，一律 ask（`unresolved-command-path`）：
     - 以 `~` 开头；
     - 含 `%VAR%`；
     - 含 `$env:`、`$HOME`、`${…}`、`$(…)`。
   - 能确定是授权目录内的照常处理。
6. **系统类，直接 deny**
   - 加入 `system-configuration`：`format`、`diskpart`、`fsutil`、`bcdedit`（已有）、`cipher /w`、`vssadmin`、`wbadmin`、`takeown`、`icacls` 修改类参数（`/grant`、`/deny`、`/remove`、`/setowner`、`/reset`）。
   - 对已有的 `system-configuration` 判定，确认它们在 trusted 下仍然 deny。
7. **类别准确**
   - `format`、`robocopy /MIR`、`Start-Process … del` 等命令，审批卡和证据里显示的类别必须是真实类别（`system-configuration` / `delete`），不能只显示 `ambiguous-command-path`。
   - 多个原因并存时都列出。
8. **confirmed 模式**判定完全不变。

## 测试

- 审查表中 21 条命令全部写成用例，断言每条的 `decision` 和关键 `reason`：
  - 系统类 → deny；
  - 删除 / 动态 / 路径类 → ask；
  - 修正后不允许任何一条是 allow。
- 每个新规则配对反例，证明普通命令仍然 allow：
  - `npx tsc -p .`、`pnpm exec vitest run`；
  - `pwsh -File scripts\build.ps1`（脚本在授权目录内）、`cmd /c` 后面跟一个本身安全的命令（递归后 allow）；
  - `node scripts/gen.mjs`、`python tools/gen.py`；
  - `robocopy src out`（不带 `/MIR`）；
  - `Set-Content out\a.txt x`（目录内）。
- 包装器递归深度限制；引号、转义字符在包装器参数里的处理。
- confirmed 模式原有用例结果全部不变。
- build、test、typecheck、lint、format:check、`git diff --check` 全部通过。
