## 背景

用户日常在 Harness 里聊天、让模型干活时，下载文件、联网、写项目目录外的文件这类操作都会弹出审批，每次都要切回 Harness 点一下，太麻烦。用户要两样东西：

1. **日常自动审批**：普通会话里，普通操作自动批准；只有删除、发布这类危险操作才问人。不需要先建“目标”。
2. **在桌宠里审批**：真的需要人批准时，在桌宠的信封里就能批，不用切回 Harness。

Harness 自己只有两档：“需确认”（`ask`，什么都问）和“完全访问”（什么都不问，连删除也不问）。Auto 审查要另装插件，本机没有。所以要自己做。

Harness 的审批通过回答者链进行：`ApprovalService.request` 调用 `ctx.waterfall(..., 'approval/request', req, fallback)`。本任务在链上加两个回答者，顺序为：

1. **WhaleMaid 自动审批**：能确定是普通操作的，直接“允许一次”；其余交给下一个。
2. **桌宠**：与 Harness 自己的界面竞争，先答者生效。
3. **Harness 界面**：现有的。

## 第一部分：WhaleMaid 日常自动审批（提交到 WhaleMaid 仓库）

### 开关与范围

- WhaleMaid 设置里加 **“日常自动审批”**，**默认关闭**，中英文案。开启时弹出风险说明，内容与高权限模式的说明一致：危险操作按命令文字识别，只能尽力而为，脚本内部做了什么看不到。用户确认后才生效。
- **只作用于普通会话。** 以下会话一律不自动批准，直接交给下一个回答者：
  - WhaleMaid 自动任务会话（标题以 `[WhaleMaid]` 或旧的 `[WhaleDot]` 开头，或首条消息以 `WhaleDot: execute this single task` 开头；或在 WhaleMaid 执行登记中的会话）。这些会话里出现的审批就是高权限模式要人来批的危险操作，**绝不能**被自动批准。
  - 大肥鱼会话；
  - 子代理会话；
  - 已归档会话。

### 判断规则

- 复用 `@whalemaid/core` 中高权限模式的命令识别（`inspectTrustedCommand` / `classifyCommand`），“授权目录”取该会话的工作目录。
- **自动“允许一次”**的情况：
  - 是 shell 命令；
  - 能完整解析；
  - 识别结果不属于任何危险类别。

  联网下载到项目目录内、读写项目目录内文件、运行构建和测试等，属于这一类。
- **交给人**的情况：
  - 删除、发布、安装 / 卸载、上传、动态执行、越界路径、进程控制等危险类别；
  - 系统配置类命令。高权限模式里这类是直接禁止的，日常模式下也交给人，WhaleMaid 不替人拒绝；
  - 无法解析的命令；
  - 非 shell 工具的审批；
  - 拿不到命令文字的审批。
- WhaleMaid **只会自动“允许一次”或交给下一个**，从不替人“拒绝”，也不修改会话的审批策略或权限预设。

### 记录

- 每次自动批准都记一条：时间、会话 ID 与会话名、工作目录、命令（截断到 500 字）、识别结果。保留最近 1000 条。
- 面板加 **“自动审批记录”** 列表，并提供“关闭日常自动审批”的快捷入口。
- 交给人的那些不需要记。
- 记录中不得出现环境变量值或密钥；命令文字里出现的疑似密钥，用现有脱敏函数处理。

### 测试

- **自动批准**：普通命令；
- **交给下一个**：
  - 危险类别；
  - 无法解析；
  - 非 shell 工具；
  - 拿不到命令；
  - 自动任务会话（新旧两种标题和执行前缀）；
  - 大肥鱼、子代理和已归档会话；
- 开关关闭时不参与；
- 从不产生“拒绝”；
- 记录内容已脱敏。

`pnpm build`、`pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm format:check` 全部通过。

## 第二部分：在桌宠里审批（提交到鲸鱼插件仓库）

### 宿主端

- 新增一个与 `InboxQuestions` 对称的审批回答模块：
  - 只登记**仍在等待**的审批；
  - 会话结束、请求被撤回或 Harness 先答时，立即移除。
- 下发给桌宠的内容只包括：
  - 审批 ID、会话 ID、会话名；
  - 工具名；
  - 可读原因：截断到 600 字，去掉控制字符；
  - 创建时间。

  **不下发**工具的完整参数。
- 桌宠的回答走现有已校验的 IPC 和 Host 通道，与聊天、提问回执的校验一致：
  - 来自本窗口主 frame；
  - 审批 ID 精确匹配且仍在等待；
  - 答案只能是 `allow-once` 或 `reject`。

  过期、重复或不匹配的回答一律拒绝，并返回明确的失败码。
- **不提供**“总是允许”“本会话都允许”之类的选项，不修改审批策略。

### 桌宠界面（两种界面风格都要做）

- 待审批事项出现在信封里，标记为“需要批准”，信封计数包含审批。
- 打开后显示：
  - 来自哪个会话；
  - 要做什么，即可读原因；
  - “允许一次”和“拒绝”两个按钮，以及“去 Harness 查看”入口（打开源会话）。
- **防误触**：
  - “允许一次”不是默认焦点，按回车不会触发允许；
  - 面板打开后 1 秒内允许按钮不可点；
  - 拒绝可以立即点。
- 回答后显示“已允许”或“已拒绝”，然后移出信封。Harness 先答了的，显示“已在 Harness 处理”后移出。
- **安静模式**：照常只亮信封、不弹框。普通模式：新的审批像提问一样弹出提醒。
- 设置里加开关 **“在桌宠里回答审批”**，**默认开启**，中英文案。关闭后，审批只计入信封并提示去 Harness，桌宠不加入回答者链。
- 菜单、托盘不提供审批按钮。

### 文档

`docs/usage.md` 和 `docs/session-chat-contract.md` 说明：

- 审批可以在桌宠里回答，只有“允许一次 / 拒绝”；
- 与 Harness 竞争时先答者生效；
- 防误触规则；
- 开关的作用；
- WhaleMaid 开启日常自动审批后，普通操作不会到达桌宠。

### 测试

- **单元**：
  - 竞争：桌宠先答时 Harness 一侧被撤回；Harness 先答时桌宠一侧被撤回；
  - 迟到、重复、伪造 ID、非法答案一律被拒绝；
  - 下发内容不含工具参数；
  - 开关关闭时，不加入回答者链；
  - 会话结束时清理登记。
- **界面（Chromium）**：
  - 两种界面风格下都能显示和回答；
  - 1 秒防误触；
  - 回车不触发允许；
  - 安静模式下不弹出；
  - 中英文案。
- `npm test`、`npm run test:inbox-ui`、`npm run test:desktop`、`npm run verify:metadata` 全部通过。

## 验收（隔离环境）

环境：profile `whaledot-p02`，启动命令 `$env:DSH_PET_TEST_DEBUG_PORT='9498'; & .\scripts\dev-host.ps1 -UseUiKey`；测试鲸鱼使用 `DSH_PET_TEST_DATA_DIR`。

在 `.dsh-dev/` 下建一个临时 Git 仓库，作为普通会话的工作目录，权限预设为“需确认”。

**日常自动审批**（开启）：

1. 让模型下载一个小文件到项目目录内。确认：
   - 没有弹出审批，命令执行了；
   - 自动审批记录里有这一条；
   - Harness 会话日志中 `approval/decided` 为允许一次。
2. 让模型删除仓库内一个临时文件：自动审批**不**放行，审批出现在桌宠信封里。

**桌宠审批**：

3. 在桌宠里点“拒绝”：命令没有执行；Harness 里的审批卡已结束，显示为拒绝。
4. 再造一次删除审批，在桌宠里点“允许一次”：命令执行，Harness 一侧同步结束。
5. 再造一次，在 Harness 里先回答：桌宠一侧显示“已在 Harness 处理”并移出信封。
6. 安静模式下再造一次：只亮信封，不弹框。
7. 关闭“在桌宠里回答审批”：桌宠里只有提示，没有按钮，在 Harness 里正常回答。

**自动任务会话不受影响**：

8. 用 WhaleMaid 高权限目标造一个危险审批：日常自动审批开着也**不会**放行，仍然要人批准。

**关闭日常自动审批**：

9. 重复第 1 步，审批照常出现，可以在桌宠里批。
