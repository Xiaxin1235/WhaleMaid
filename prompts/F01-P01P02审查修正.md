# F01 P01/P02 审查修正（小任务，先于 P03 执行）

审查结论：P01、P02 整体质量好，查证笔记扎实，下面三处需要修。只改列出的内容，不做其他重构。

## 1. 【core】`mergeProposedTasks` 会让一个坏提议卡死整个目标

**现状**：`packages/core/src/goal-graph.ts` 的 `mergeProposedTasks(existing, proposed)` 只按 key/id 去重：
- 不检查提议任务的 `goalId` 是否属于目标——另一个目标的任务会被混进来；
- 不检查 `dependsOn` 是否指向存在的任务、是否成环。

而 `readyTasks` / `selectNextTask` 遇到无效 DAG 时直接返回“无可执行任务”。结果：planner（模型）一次提出一个依赖写错的任务，这个目标就**静默停摆**，而且看起来像“没有任务可做”，不会触发阻塞通知。

**修改**：
- 签名改为 `mergeProposedTasks(goalId, existing, proposed) → { tasks: Task[]; rejected: { task: Task; reason: 'foreign-goal' | 'duplicate' | 'dangling-dependency' | 'cycle' }[] }`。
- 逐个处理提议：`goalId` 不符 → 拒绝；与已有任务或已接受的提议重复 → 拒绝（`duplicate`）；把它加入后 `validateDag` 失败 → 拒绝该条（依赖缺失为 `dangling-dependency`，成环为 `cycle`），**其余合法提议照常接受**。
- 保证：只要 `existing` 是合法 DAG，返回的 `tasks` 也一定是合法 DAG（写成测试断言）。
- `selectNextTask` 在 DAG 无效时的返回原因从 `no-ready-task` 改为新增的 `invalid-graph`，让 Host 能区分“没事做”和“数据坏了”（后者要发阻塞通知）。同步更新 `TaskSelection` 类型与 `docs/core-domain.md`。

## 2. 【host】会话中途销毁不能记为 `aborted`

**现状**：`packages/host/src/bridge/run-tracker.ts` 在收到 `session-disposed` 时把 `endReason` 记为 `'aborted'`。

会话在执行中被销毁时，工具可能已经改了文件、跑了一半命令，结果是**不确定**的。架构原则 5 要求这种情况进入 `UNKNOWN` 并先核对外部状态；记成 `aborted` 会让后续逻辑当作“明确中止”处理，可能直接重试。

**修改**：`session-disposed` 结束的 run 记 `endReason: 'unknown'`，并在 `RunState` 增加 `endSource: 'turn-end' | 'session-disposed'` 以保留来源。更新对应测试与 `docs/p02-report.md` 中的表述。

## 3. 【host】依赖版本与 status 写入

- `packages/host/package.json`：`@deepseek-ai/dsh-home-paths` 与 `@deepseek-ai/schemastery` 当前精确锁定版本。改为 `^` 范围（`^0.2.1-rc.2`、`^3.18.4`），与社区插件惯例一致（参考 dsh-llm-deepseek-vision 的 `"@deepseek-ai/schemastery": "^3.18.1"`）。
- `status.json` 改为原子写：先写同目录临时文件再 `rename`。若 `.dsh-ref` 中的 `@deepseek-ai/dsh-atomic-write` 有适合的公开 API 可直接用（查证并在 `docs/dsh-api-notes.md` 第 8 节补一句出处）；否则自己实现，十几行即可。
