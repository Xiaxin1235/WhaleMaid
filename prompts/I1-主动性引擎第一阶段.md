# I1 WhaleMaid：主动性引擎第一阶段（发现与面板，不打扰）

**前置**：`master` 工作区干净（本提示词文件除外），先跑一遍 `pnpm install --frozen-lockfile`、`pnpm build`、`pnpm test`，确认基线通过。

**必读**：[docs/主动性引擎设计.md](../docs/主动性引擎设计.md)。本任务只实现其中的**阶段 I1**；文档里 I2–I4 的内容（建议卡、询问、反馈按钮、自动降级、大肥鱼的经历与收工汇报、模型辅助检测）**本次都不做**，但数据结构要为它们留好位置。

> **改名说明**：项目已从 WhaleDot 改名为 WhaleMaid（包名 `dsh-whalemaid`、`@whalemaid/core`）。以下内容**有意保持旧名**，不要改：本地目录 `D:\dsh_plugins\WhaleDot`、插件配置 ID 和数据目录 `whaledot`、大肥鱼预设 `whaledot-companion`、隔离 profile `whaledot-p02`。

## 目标

WhaleMaid 从已有的验收、任务、预算、通知记录里，用规则找出“值得提一下”的事（称为**发现**），在面板“发现”列表中展示，并把重要的几条放进大肥鱼的每日简报。**这一阶段不单独发通知、不弹信封、不调用模型、不执行任何动作。**

## 实现

### 1. 核心（`packages/core/src/initiative/`，纯函数，不读时钟、不做 IO）

- `Opportunity` 类型按设计文档第 4.2 节，`status` 本阶段只会用到 `open` 和 `expired`，其余值保留给 I2。
- 七个检测器，每个是纯函数：输入为记录快照和 `now`，输出候选机会列表。ID、触发条件和默认最高分级按下表（与设计文档第 5、10 节一致）：

  | 检测器            | 触发条件（初值）                                                                         | 默认最高分级 |
  | ----------------- | ---------------------------------------------------------------------------------------- | ------------ |
  | `repeatedFailure` | 同一目标内，同一失败签名在 ≥3 个任务或 ≥3 次尝试中出现                                   | L2           |
  | `stallWarning`    | 进度连续“无变化”的轮数达到 `maxStallRounds - 1`                                          | L2           |
  | `noAcceptance`    | 目标中 ≥2 个 `NOT_SCORABLE` 任务，或 report-only 任务占比 ≥50%                            | L1           |
  | `budgetBurn`      | 已用尝试或时间预算 ≥80%，而通过的任务 ≤50%                                               | L3           |
  | `pendingBacklog`  | 决策卡投递后 24 小时未处理，且该目标因此停着                                             | L2           |
  | `idleGoal`        | 授权有效、未完成，但自动推进关闭或暂停 ≥7 天                                             | L1           |
  | `leftovers`       | 目标完成，但有被跳过或取消的任务（或查证中确认的结构化遗留字段）                         | L1           |

- **失败签名**：对验收命令和失败输出做归一化（去掉绝对路径、行列号、时间戳、十六进制地址、数字序列、临时目录名）后取哈希。**只存哈希和验收命令，不存输出原文**；面板展示证据时按 ID 回读原记录（原记录本身已脱敏）。
- **评分**：`score = 严重度 × 置信度 × 相关度 × 新颖度`，各项定义见设计文档第 6 节；严重度表写成常量，便于以后调整。
- **最终分级**：一个纯函数 `resolveLevel(candidate, settings)`，综合得分阈值（< 0.3 为 L0）、检测器默认最高分级、用户为该检测器设定的最高分级、渠道开关。**渠道关闭时逐级降级**：L3/L2 渠道关闭 → 降到 L1；L1（简报）关闭 → 降到 L0。本阶段 L2/L3 渠道尚未实现，所以实际最高只会到 L1，但函数要按完整规则写并测试。
- **去重与冷却**：`dedupeKey = detector + 目标/任务 + 证据签名`；同一去重键已有 `open` 记录时更新证据和得分，不新增。过期时间默认 7 天。

### 2. 宿主（`packages/host`）

- 新增 `opportunities` 表及迁移，字段按设计文档第 4.2 节。证据只存引用 ID 和哈希。
- **触发**：验收结论写入、任务或目标状态变化后，延迟合并 30 秒运行一次检测；宿主启动时补做一次；每个本地日首次检测时运行按时间判断的检测器（`pendingBacklog`、`idleGoal`）。检测只读增量，单次运行有超时，失败只写调试日志，**不能影响执行、验收和通知主流程**。
- **配置**（Schemastery，接入现有 WhaleMaid 设置）：
  - `initiative.enabled`，默认开；
  - `initiative.detectors.<id>.enabled`（默认开）与 `.maxLevel`（默认值见上表）；
  - `initiative.channels.brief`，默认开；`initiative.channels.cards`、`initiative.channels.asks` **先加上、默认关、本阶段不起作用**，面板上标注“下一版本提供”；
  - 关闭任何开关都不删除已有记录。
- **每日简报**：在现有简报快照中加入“最近发现”，只取未过期的 L1 及以上、最多 3 条、按得分排序，固定模板文案（中英文），不调用模型。遵守现有“第一次非空快照每天固定”的规则；简报关闭或 `channels.brief` 关闭时不加入。
- **大肥鱼只读工具**：新增一个伙伴工具（加入 `COMPANION_TOOL_NAMES`）用于查询最近的发现及其证据摘要，便于你问“最近有什么发现”。只读，不能改状态。

### 3. 面板

- 新增“主动性”卡片，三部分：
  1. **发现列表**：按目标分组，显示检测器名称、固定模板摘要、得分、分级、时间；展开可看证据（点击跳到对应目标详情或验收日志）；支持“删除这条记录”（二次确认）。
  2. **开关**：总开关；每个检测器一行（开关 + 最高分级下拉）；三个渠道开关（卡片、询问两项置灰并标注“下一版本提供”）；“恢复默认”。
  3. **简单统计**：近 7 天各检测器产生的发现数量。采纳率等反馈指标留给 I2，本阶段不显示空表。
- 中英文文案齐全，跟随现有 `language` 设置。

## 不要做

- 不发通知、不进通知中心、不弹桌宠信封、不调用 `decideDelivery` 投递（只为 I2 预留通知类型名 `initiative`，不接线）。
- 不调用模型，不读普通会话正文。
- 不执行任何动作，不改目标、任务、授权、预算的任何状态。
- 不改执行、验收、停滞判断的现有逻辑。
- 不改动 `../dsh-coopanion`。

## 测试

- 每个检测器：触发、刚好不触发（阈值边界）、数据缺失时不报错且不触发。
- 失败签名归一化：同一错误在不同路径、行号、时间戳、临时目录下得到相同签名；两个不同错误不碰撞。
- `resolveLevel` 表驱动测试，覆盖：得分低于阈值、检测器上限低于默认分级、渠道关闭逐级降级、总开关关闭。
- 去重：同一去重键重复检测只更新不新增；过期后可以重新产生。
- 简报：有发现时加入最多 3 条且按得分排序；当天快照固定后新发现不改变当天快照；简报关闭时不加入。
- 检测失败不影响主流程：模拟检测器抛错，验收与状态流转照常完成。
- 存储迁移：从现有数据库升级不丢数据；导出包含新表（若现有导出覆盖其他表）。
- 全量 `pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm format:check` 通过。

## 隔离实测

在隔离环境 `whaledot-p02`（`.dsh-dev`，端口 3182，**不碰日常 profile，不在设了 DSH_HOME 的终端里启动桌面版 Harness**）里：

1. 在一个临时 Git 项目里建一个目标，验收命令故意用一个会因同一原因失败的命令（例如引用不存在的文件），让它在 3 次尝试中失败；确认面板出现 `repeatedFailure` 发现，证据能点开。
2. 确认第二天（可通过注入的时间参数或测试替身模拟）大肥鱼的简报里出现这条发现，文字是固定模板。
3. 关闭该检测器，确认不再产生新发现、旧记录保留；恢复默认后重新开启。
4. 截图或记录面板“主动性”卡片三部分的实际显示。
