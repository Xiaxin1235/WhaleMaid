# C05 鲸鱼插件：有未处理异常时不要流眼泪

**前置**：C04 已提交（`75a6b1f`），工作区干净。用户日常 profile 通过 `link:` 使用本仓库构建产物：完成并提交后执行 `npm run build`，用户完全退出并从开始菜单重开 Harness 即生效。

## 用户反馈
有消息没看的时候，小鲸鱼一直在流眼泪，很违和，“眼泪很奇怪”。

## 原因（已在源码确认，行号以当前源码为准）
- `web/pet.js` 中按 mood 映射表情的两处——`render` 中的 `word` 映射（约 355 行：`error: 'sad'`）与 `controls.expression` 映射（约 360 行：`error: 'sad'`）——把 `error` 映射为 `sad`。
- `web/upstream/kit/body.js` 中 `sad` 表情带 `emit: 'tear'`，每 0.8 秒发出一滴眼泪粒子；`cry` 还带泪痕，但目前没有状态会触发 `cry`。
- 小信封中有未处理的异常条目时 mood 持续为 `error`，因此会长时间流泪。

## 修改（只改映射与状态逻辑，不改 `web/upstream/` 中引入的上游动画与角色代码）
1. `error` 改用**不流泪**的表情：首选 `worried`（皱眉 + 汗滴）。若与 `waiting`（同为 `worried`）难以区分，可改用 `confused` 或 `pout`，并在报告中附截图或说明理由。两处映射保持一致。
2. 异常是“提醒”而不是“持续情绪”：错误发生时表现一次（可配一次短动作，如 `shake`），之后若用户已查看或点掉该异常（使用 C04 的已处理记录），立即回到正常空闲表情；未查看时维持不流泪的表情。
3. 全局约束：除用户在角色面板中手动预览“难过/大哭”外，**任何自动状态都不得触发带眼泪的表情（`sad`、`cry`）**。增加测试：遍历所有 mood、等待/异常组合以及陪伴/NPC 自动表情，断言结果不含 `sad`、`cry`。
4. 同步 `docs/usage.md` 中关于异常时神态的描述。

## 测试
- 上述映射与约束的单元测试；`npm test`、`npm run test:inbox-ui` 通过；涉及原生窗口时跑 `npm run test:desktop`。
