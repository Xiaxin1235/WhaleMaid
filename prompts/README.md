# 给 GPT 的实现提示词

## 使用方法
每次发给 GPT：**`00-通用上下文.md` 全文 + 一个任务提示词全文**。按顺序执行，一个完成并经审查后再发下一个。

| 顺序 | 文件 | 里程碑 | 状态 |
|---|---|---|---|
| 1 | `P00-仓库脚手架.md` | M0 | 待执行 |
| 2 | `P01-core领域模型与状态机.md` | M0（M2 地基） | 待执行（可与 P02 并行，二者不改同一目录） |
| 3 | `P02-host插件骨架与事件桥.md` | M0 | 待执行 |
| 4 | `P03-Desktop桌宠窗口.md` | M0 | 待执行（依赖 P02 的协议包） |
| 5 | P04 通知中心 | M1 | 待 P02 回报后编写 |
| 6 | P05 智能选项 + 可靠操作路由 | M1 | 同上 |
| 7 | P06 存储层 + 授权范围 | M2 | 同上 |
| 8 | P07 目标录入 | M2 | 同上 |
| 9 | P08 执行通道（worktree + DSH 会话 + ToolGate） | M2 | 依赖 P02 对 gateway / pre-execute 的查证结果 |
| 10 | P09 独立验收 + 决策 + Scope Guard | M2 | 同上 |
| 11 | P10 调度器 + 三阶段闭环 E2E | M2 | 同上 |

P04 以后故意没有提前写：它们依赖 P02 对 DSH 真实 API（事件结构、审批事件、gateway 方法、`tools/pre-execute` 签名）的查证结果，提前写死容易让 GPT 臆造接口。

## 每步完成后
把 GPT 的回报贴回给 Claude（或直接说“P0x 完成了”），Claude 会读代码、跑测试、审查，然后给出修正提示词或下一个提示词。
