# 给 GPT 的实现提示词

## 使用方法
每次发给 GPT：**`00-通用上下文.md` 全文 + 一个任务提示词全文**。按顺序执行，一个完成并经审查后再发下一个。

桌宠由 `@takboo/dsh-coopanion` 提供，WhaleDot 只做 Autopilot（见 `docs/架构与开发路线.md` v0.2）。

| 顺序 | 文件 | 里程碑 | 状态 |
|---|---|---|---|
| 1 | `P00-仓库脚手架.md` | M0 | 待执行 |
| 2 | `P01-core领域模型与状态机.md` | M0（M2 地基） | 待执行（可与 P02 并行，二者不改同一目录） |
| 3 | `P02-host插件骨架与事件桥.md` | M0 | 待执行；产出 `docs/dsh-api-notes.md`，后续提示词都依赖它 |
| 4 | `P03-WhaleDot面板骨架.md` | M0 | 待执行（依赖 P02 的查证笔记） |
| 5 | P04 通知策略 + 决策渠道 | M1 | 待 P02 回报后编写 |
| 6 | P05 智能选项 + 可靠操作路由 | M1 | 同上 |
| 7 | UP1 给 dsh-coopanion 提对外通知/选项接口的 PR（可选） | M1 | 视 P02 查证的 `userQuestions` 能力决定 |
| 8 | P06 存储层 + 授权范围 | M2 | 待编写 |
| 9 | P07 目标录入 | M2 | 待编写 |
| 10 | P08 执行通道（worktree + DSH 会话 + ToolGate） | M2 | 依赖 P02 对 gateway / pre-execute 的查证 |
| 11 | P09 独立验收 + 决策 + Scope Guard | M2 | 待编写 |
| 12 | P10 调度器 + 三阶段闭环 E2E | M2 | 待编写 |

P04 以后故意没有提前写：它们依赖 P02 对 DSH 真实 API（事件结构、提问/审批、gateway 方法、`tools/pre-execute` 签名）的查证结果，提前写死容易让 GPT 臆造接口。

## 每步完成后
把 GPT 的回报贴回给 Claude，Claude 会读代码、跑测试、审查，然后给出修正提示词或下一个提示词。
