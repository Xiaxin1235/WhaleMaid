# C10 鲸鱼插件：会话名使用 Harness 的会话标题

**前置**：`whaledot-local` 分支工作区干净，最新提交至少包含 `e1bb4c3 feat: quiet mode keeps new messages in the envelope`。若工作区不干净，先停下说明。先跑一遍 `npm test` 与 `npm run test:inbox-ui`，确认基线通过。

**执行环境**：本任务要写 `D:\dsh_plugins\dsh-coopanion`，报告和证据写在 `D:\dsh_plugins\WhaleDot`，还要能运行 Git、Chromium 和 Electron。会话必须在开始时就具备这些权限。如果发现无法写入或无法启动，立即停下说明，不要只写一半代码。

## 问题

桌宠会话列表、信封、提醒标题里的会话名，一律取**第一条用户消息的前 64 个字**，见 `src/model.ts` 的 `describe`：

```ts
if (!item.prompt) item.label = Array.from(text).slice(0, 64).join('');
```

插件从不读取 DSH 的 `session/title` 事件，因此出现两种结果：

- 用户在 Harness 里手动改的名字、DSH 自动生成的标题，在桌宠里都不显示。
- WhaleDot 的自动任务会话全部显示为 “WhaleDot: execute this single task within the immutable authoriz…”，看不出是哪个目标、哪个任务。

审查方已查证：WhaleDot 在发第一条消息前调用了 `sessionController.rename`，会话日志里有：

```json
{"type":"session/title","seq":5,"data":{"title":"[WhaleDot] P13B 放弃 合成验收 · 测试任务：只读 README.md 并说明","messageSeqs":[],"source":{"kind":"user"}}}
```

之后没有被覆盖。也就是说，标题在 DSH 那边是对的，只是插件没用。

这个问题也阻塞 C02。C02 用“会话标题以 `[WhaleDot]` 开头”来排除自动任务会话、不把它们的回复发给 OpenAI，按现状永远匹配不上。

## 先查证（写进回报，附出处）

1. 在当前安装的 DSH 0.2.1-rc.2 类型定义中，找到 `session/title` 事件的数据结构，以及 `source.kind` 的全部取值。出处写类型文件路径和行号。
2. 确认以下两种情况都能拿到标题：
   - 冷会话恢复：`sessionController.list` 加 `observeSession` / `snapshotEvents` 这条路径，能否看到历史 `session/title` 事件；
   - 实时会话：标题事件是否经现有 `fold` 入口到达。
3. 确认 `SessionSummary`（`session.list` 的结果）是否直接带 `title` 字段。如果带，说明是否可以用它作为恢复时的初始名字。

## 实现

1. **`src/model.ts`**
   - 处理 `session/title` 事件：会话名取**最新**一次标题，去掉首尾空白，截断规则与现有名字一致，最多 64 个字。
   - 没有标题时保持现在的回退顺序：工作目录名 → 第一条用户消息。
   - 收到标题后，后续用户消息不再覆盖名字。
   - `prompt` 字段（第一条消息摘要）照旧维护，不受标题影响。
2. **大肥鱼会话不变**
   - 当前和以往的大肥鱼会话仍按现有逻辑显示 “大肥鱼” / “大肥鱼（旧对话）”，即 `companionRole` 优先于标题。
   - 核对 `web/` 与 `desktop/tray-state.cjs` 中所有显示名字的地方，确认用的都是同一个来源。
3. **标题为空或无效**
   - 标题为空字符串或全是空白时，视为没有标题，回退到上面的顺序。
4. **影响范围**
   - 名字变化应同步到会话列表、聊天面板标题、信封卡片、提醒标题、托盘菜单。
   - 只改显示，不改会话选择、已读、完成判断等逻辑。
5. **文档**
   - `docs/session-chat-contract.md` 补一节“会话名来源”，写明优先级：大肥鱼角色名 > 最新会话标题 > 工作目录名 / 第一条消息。
