# P14 高权限执行模式（普通改文件、跑命令不再拦，只有危险操作实时问用户）

## 背景

现在 WhaleDot 执行任务时，命令只放行两类：

- 用户在授权里逐字确认过的命令（`verifyCommands`）；
- 少量已知只读命令和 `pnpm test` 一类本地测试（`LOCAL_TEST_COMMAND`）。

其余命令在 `checkAction` 里得到 `ask`，被 `ToolGate` 一律当 `deny` 处理，任务因此卡住，变成一条等用户决定的通知。用户觉得被问得太多。

本任务增加一个**按目标开启**的“高权限执行”模式：

- 授权目录内的普通改文件、跑命令直接放行；
- 只有删除等危险操作，才通过 DSH 的审批机制**实时**询问用户；
- 用户不回答就不执行。

默认关闭，关闭时行为与现在完全一致。

## 必须如实告诉用户的风险

这一段的意思要写进确认界面、`docs/usage.md` 和报告，不能淡化：

- 高权限模式下，任意命令可以读写授权目录以外的文件。例如 `node build.js` 里的脚本做什么，WhaleDot 看不到。路径限制只对文件工具和能识别的命令有效。
- 危险操作是**按命令文字识别**的，只能尽力而为。脚本内部、编码命令、间接调用里的删除可能识别不出来。
- 主要的兜底手段有三个：
  - 任务在独立 worktree 里执行；
  - WhaleDot 的检查点和回滚；
  - 授权目录以外的危险命令一律询问。

  这三个都要写清楚。

## 第一部分：查证（写进 `docs/dsh-api-notes.md` 第 28 节，附出处）

1. **`ask` 的实际效果。** `PreToolDecision` 的 `{ kind: 'ask', reason, displayReason }`（`@deepseek-ai/dsh-tools` 类型定义第 440–460 行附近）会走 approval 服务。查清以下几点：
   - 在 WhaleDot 后台执行会话里，审批提示出现在哪里：DSH 会话界面、鲸鱼桌宠的信封 / 审批卡、系统通知。
   - 没人回答时等多久、超时结果是什么；会话被中止时结果是什么。
   - `allowed-once` 之外有没有“总是允许”类选项。如果有，本模式下必须**不**提供或不采用，每次危险操作单独问。
   - 审批结果能否在 `tools/post-execute` 或事件里取到，用于审计。
2. **结果怎么落到任务上。** 审批被拒绝或超时后，模型收到什么？任务应如何结束？复用现有拒绝计数 `deniedCalls` 与证据记录。
3. **用户不在电脑前时。** 一个危险操作等待审批期间，运行一直占着名额。查清现有执行预算和超时（每次运行时长上限）如何与等待审批交互。给出处理方式：例如等待算进运行时长，超时按拒绝处理，任务进入现有的需要用户决定状态。

## 第二部分：实现

### 1. 授权字段

- `AuthorizationScope` 增加 `commandMode: 'confirmed' | 'trusted'`，默认 `'confirmed'`。
  - 它属于授权内容，**计入 scope hash**；旧授权读出为 `'confirmed'`。是否需要迁移由查证决定，旧数据不得改写。
- `'trusted'` 只能与 `workspace-write` 预设同时使用；`read-only` 下不可选。
- 只能在 P07 确认授权表单里由用户本人开启：
  - 勾选“高权限执行”后弹二次确认，展示上面的风险说明全文；
  - 已有目标要改成高权限，走现有的重新授权流程（hash 变化，自动推进需重新确认）。
- 大肥鱼不能开启。P13 的自动推进确认卡在授权摘要里显示“命令模式：高权限”。

### 2. 命令判定（core 纯函数，`checkAction` / `classifyCommand`）

`commandMode === 'trusted'` 时，`run-command` 按以下顺序判定：

1. 工作目录不在授权范围 → `deny`（不变）。
2. **危险** → `ask`（实时审批），至少包括：
   - 现有 `forbidden` 类：递归删除、`git reset --hard`、系统配置 / 注册表 / 服务。
     - 系统配置类仍然 **deny**，不提供审批；其余改为 `ask`。
   - 现有 `needs-approval` 类：`git push`、发布、安装依赖、网络上传。
   - 新增“删除”类：
     - 任何形式的单文件删除：`rm`、`del`、`erase`、`Remove-Item`/`ri`、`rmdir`/`rd`；
     - 版本库删除：`git clean`、`git rm`、`git checkout -- .`、`git restore` 不带 `--staged`、`git stash drop/clear`、`git branch -D`；
     - 把文件移到授权目录以外：`Move-Item`/`mv`/`move` 的目标在授权范围外。
   - 新增“动态执行”类：
     - `Invoke-Expression`/`iex`、`-EncodedCommand`/`-enc`；
     - `powershell`/`pwsh`/`cmd` 带 `-Command`/`/c` 的嵌套调用；
     - `node -e`、`python -c`。
   - 命令文字里出现授权目录以外的绝对路径、`..` 越出工作目录，或盘符根目录。
3. 其他命令，包括组合命令、重定向和未识别命令 → `allow`。
   - 组合命令按 `; & | &&` 拆开逐段判定，**任何一段危险就整体 ask**。拆不开、引号不配对 → `ask`。

`'confirmed'` 模式下判定完全不变；现有测试原样通过。

### 3. 门禁

- `ToolGate.check` 在 trusted 授权下，对 `checkAction` 的 `ask` 返回 DSH 的 `ask`（不再一律 deny），`displayReason` 写中英文：命令原文、危险类别、工作目录、所属目标。
- confirmed 授权下 `ask` 仍然 deny，行为不变。
- 审批结果写证据记录：允许或拒绝、类别、命令哈希，不写完整输出。
- 拒绝和超时计入 `deniedCalls`。
- 文件工具的路径与保护路径规则在两种模式下都不变；保护路径在 trusted 下依然 deny。
- 独立验收只运行用户确认过的精确验收命令，**不受**本模式影响。

### 4. 展示

- 面板目标详情和授权摘要显示“命令模式：高权限 / 逐条确认”。
- 追溯导出列出本次运行中每次危险审批的结果。
- 中英文案进 i18n。

## 测试

- **core**
  - trusted 下每个危险类别各有正反例，并分别验证 ask 与 deny（系统配置仍 deny）。
  - 组合命令拆分：一段危险 → 整体 ask；引号不配对 → ask。
  - 越界路径、`..`、盘符根 → ask。
  - 普通 build/test/格式化/脚本命令 → allow。
  - confirmed 模式下现有全部用例结果不变。
  - read-only 不能与 trusted 组合；hash 随 commandMode 变化；旧授权解析为 confirmed。
- **host**
  - 门禁：trusted 下 ask 透传为 DSH ask；confirmed 下仍 deny。
  - 审批拒绝 / 超时 / 会话中止均不执行，并留下证据与计数。
  - 保护路径在 trusted 下仍 deny；大肥鱼无入口开启。
  - 重新授权后自动推进需要重新确认；验收命令不受影响。
- build、test、typecheck、lint、format:check、`git diff --check` 全部通过。

## 手工验收（`.dsh-dev` 隔离环境，写进 `docs/p14-report.md`，证据放 `.dsh-dev/p14-evidence/`）

1. 在 P07 表单为一个虚构测试仓库开启高权限，看到风险说明与二次确认；授权摘要显示高权限。
2. 让任务执行一个未在授权里写过的普通命令（例如 `node scripts/gen.mjs` 生成文件），不弹审批，直接完成。
3. 让任务删除仓库里的一个文件，弹出实时审批：
   - 记录审批出现在哪里（DSH 界面 / 桌宠）；
   - 选拒绝后文件仍在，任务按查证结论结束。
4. 再次触发删除，选允许，文件被删除。证据记录可见。
5. 命令里写授权目录以外的路径（例如 `type C:\Windows\win.ini`），弹审批，拒绝。
6. 同一仓库切回逐条确认模式：第 2 步的命令重新被拦。
7. 清理：关闭自动推进，停止测试进程（3182 / 9498 无监听），恢复隔离配置。

## 不做

- 不做“总是允许”或按类别永久放行。
- 不放开系统配置类命令；不改独立验收；大肥鱼不能开启或提议开启本模式。
- 不改鲸鱼插件。若审批在桌宠里显示有问题，写进报告，另开 C 任务处理。
