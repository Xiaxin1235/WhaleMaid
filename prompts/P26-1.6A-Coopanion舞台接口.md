# P26 Coopanion fork：舞台接口与新动作（为 WhaleMaid 1.6 宅邸准备）

**仓库**：`D:\dsh_plugins\dsh-coopanion`，分支 `whaledot-local`（当前已发布 0.5.8，提交 `cdcf9dc`）。**这是 AGPL-3.0-or-later 仓库，所有改动只在这里做。**

**前置**：工作区干净；跑一遍该仓库的元数据、构建、类型、单元与浏览器测试，确认基线通过。

**必读**：WhaleMaid 仓库中的 [docs/项目世界设计.md](../docs/项目世界设计.md)（尤其 5、6.1 节），了解宅邸要怎样使用大肥鱼。

## 目标

让 WhaleMaid（MIT，独立插件）能在它的“宅邸”画面里（1.6 中为默认关闭的实验功能）**请 Coopanion 画出大肥鱼**，而不复制任何 Coopanion 的代码或角色素材：

1. 一个公开、带版本号的**舞台接口**：WhaleMaid 给出一块透明区域和指令，Coopanion 用自己的代码与素材绘制角色。
2. 新增宅邸需要的动作：**行走循环、坐姿工作、睡姿**（用现有身体部件组合，不新增贴图）。
3. 一个“**桌宠暂时离开桌面**”的公开控制：WhaleMaid 打开宅邸时桌宠隐藏，离开后回来。

## 先查证（写进报告，附代码出处）

1. 角色渲染：`web/upstream/whale/figure.js` 的 `createWhaleFigure` / `createWhaleBody`，以及 `web/pet.js` 中 `loadBody`、设置里的 `character-preview` 如何创建一个只画角色的实例；能否在普通浏览器页面（非 Electron）里独立运行。
2. 资源投递：现在的桌宠页面经 `src/figure-server.ts` 的回环 HTTP 服务加载，**远程浏览器访问 Harness 时拿不到回环地址**。确认 `src/index.ts` 里 `connection.fetch.register` 能否注册 **GET** 路由来投递舞台页面与角色素材，以及鉴权方式（只给已认证的 owner）。
3. 嵌入方式的取舍：(a) 舞台作为可嵌入页面，由 WhaleMaid 用透明 iframe 叠在场景上，双方用 `postMessage` 通信；(b) Coopanion 的客户端插件提供一个服务或组件，WhaleMaid 的客户端插件可选注入。比较两者在 DSH 客户端中的可行性、隔离性和性能，选一种并写明理由；**(a) 的许可边界最清楚，若可行优先选 (a)**。
4. 现有显示控制（`ctx.coopanion.command('hide')` 等）与用户手动隐藏的状态如何区分；多个客户端同时控制时的表现。

## 实现

### 1. 舞台接口（版本 `stage/1`）

- 一个只画角色的透明舞台：背景透明、无 UI、无文字、不播放声音、不读用户会话内容。
- 指令（只接受白名单字段，校验类型和范围，未知字段忽略）：
  - `place`：角色在舞台中的位置（像素）、缩放、朝向（左 / 右）；位置变化时可选平滑移动时长。
  - `motion`：`idle`（站立）、`walk`（行走循环）、`sit-work`（坐着干活）、`sleep`（睡觉），以及现有的情绪表情（开心、害羞、惊讶、思考等，名称以现有动作表为准）。
  - `light`：环境光色调（白天 / 傍晚 / 夜晚 / 台灯），只做整体色调叠加。
  - `pause` / `resume`：页面不可见时暂停渲染。
- 事件：`ready`（含协议版本与可用动作列表）、`click` / `hover`（只报告“角色被点击 / 悬停”，不带其他信息）、`error`。
- 若选 iframe 方案：严格校验消息来源（只接受同一 Harness 源的父页面）、不暴露任何可读写 Coopanion 设置或会话的消息；舞台页面在沙箱中运行，资源全部来自已认证的 DSH 路由。
- **遵守“减少动态效果”**：开启时只显示静止姿势。
- 写一份协议说明 `docs/stage-protocol.md`：字段、动作名、事件、版本规则、错误处理。**WhaleMaid 只依据这份说明实现自己的一侧，不复制本仓库代码。**

### 2. 新动作（不新增贴图）

- `walk`：腿部与身体的行走循环（可在现有 `hop` 的基础上改为连续步伐），左右朝向用翻转。
- `sit-work`：坐姿（身体下沉、腿部弯折或被桌子遮挡均可），双手做书写或敲键盘的小幅循环，偶尔眨眼、呆毛轻摆。
- `sleep`：以现有 `sleepy` 为基础，闭眼、缓慢呼吸，可配小“z”气泡（若现有素材里没有，不画也可以）。
- 桌面桌宠是否开放这些新动作由你决定，但默认行为不能改变。

### 3. 桌宠“暂时离开桌面”

- 公开的控制（例如服务方法 `away(clientId)` / `back(clientId)`，名称以实现为准，写进协议说明）：按客户端计数，**第一个** away 时桌宠先播放一次小跳再隐藏，**最后一个** back 或客户端断开时恢复。
- **用户手动隐藏桌宠时**：away / back 不改变它，恢复时仍保持用户的隐藏状态。
- 宿主重启、客户端断线不会让桌宠永远处于离开状态（断线视为 back；重启后清零）。
