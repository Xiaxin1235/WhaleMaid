# P08 执行通道：隔离 worktree + 驱动 DSH 会话 + 工具门禁（M2 核心）

这是 WhaleDot 第一次真正让 DSH 干活。**安全优先于功能**：任何拿不准的地方，宁可拒绝、停下、记录，也不要放行。

## 第零部分：P07 审查遗留（先做，单独提交）

1. `packages/host/package.json`：`@deepseek-ai/dsh-llm` 与 `@deepseek-ai/dsh-agent-default-model` 只被 `import type` 使用，从 `dependencies` 移到 `devDependencies`（避免安装插件时拉入重复的宿主包）。确认构建产物中没有对它们的运行时 import。
2. **嵌套目录中的密钥文件没有受保护**：默认保护只覆盖项目根下的 `.env*`，`packages/api/.env`、`*.pem`、`id_rsa*` 等不受保护，而且 `protectedPaths` 同时阻止读取，所以这关系到密钥是否会被读进模型上下文。
   - core：`AuthorizationScope` 新增 `protectedNames: string[]`（文件名通配，只支持 `*`，大小写不敏感，匹配路径中**任意一级**的文件或目录名）。默认值 `['.env', '.env.*', '*.pem', '*.key', 'id_rsa*', 'id_ed25519*', '.npmrc', '.pypirc']`。`isPathAllowed` 对命中任意 protectedNames 的路径返回 false。纳入 scope 规范化与哈希（这是一次 schema 变更：写存储迁移，旧 scope 读出时补默认值并在面板标注“旧版授权，建议重新确认”）。
   - P07 确认页显示并允许增加（不允许删除默认项）。
3. 提交：`fix: type-only host deps and name-based secret protection`。

## 目标

面板上的目标详情提供“执行下一个任务”按钮。点击后 WhaleDot：选任务 → 在**独立的 Git worktree** 里创建一个钉住权限的 DSH 会话 → 发送任务提示词 → 全程用工具门禁把会话限制在授权范围内 → 会话结束后提交检查点、记录证据 → 把任务推进到 `VERIFYING`（P09 才做验收判定）或相应的异常状态。

**本任务只做“手动触发执行一个任务”**。自动连续推进是 P10。

## 第一部分：查证（写进 `docs/dsh-api-notes.md` 第 15–18 节，结论 + 出处 + 不确定点）

15. **后台创建会话的身份**：笔记第 3 节写明 gateway `invoke` 需要必填的 `peer`。本任务的手动触发来自面板请求，可以用该请求经 `admit` 得到的 owner peer；但 **P10 的后台调度没有面板请求**。查清：
    - 插件能否不经 gateway，直接调用 `ctx.sessionController`（或等价服务）的 create / prompt 方法；它们是否需要 peer、需要什么；
    - 是否存在宿主/系统级的 principal 供插件后台使用；
    - **禁止**把某次浏览器请求的 peer 保存下来留给以后使用（它的生命周期属于那次连接）。
    - 结论：手动触发与后台触发各自用什么方式，P08 实现的接口要能被 P10 直接复用。
16. **取消/中止一个正在运行的会话回合**：对应的 API（会话或 agent 层的 cancel / abort），以及中止后 `turn/end` 的 reason。用于超时与撤销授权。
17. **DSH 内置工具清单与参数结构**：在目标宿主的默认 agent 预设下，模型能用哪些工具（读、写、编辑、搜索、shell/pwsh、web、子 agent、提问、计划、待办、schedule、jobs 等），每个工具的名字和参数里路径/命令字段的位置。参考 `.dsh-ref` 中 `dsh-tool-*` 包的 README 与声明。
18. **子 agent 的归属**：WhaleDot 会话里模型调用子 agent 时，`tools/pre-execute` 的 `exec.agent` 指向谁；如何通过 `parent` / `rootCallId` / 会话 fork 关系判断它属于某个 WhaleDot 会话。

## 第二部分：core（纯函数，带测试）

### 1. 工具调用 → 动作意图 `packages/core/src/tool-intent.ts`
- `toolCallToIntents(toolName, args, ctx: { cwd }) → { intents: ActionIntent[] } | { unknown: true }`：用第 17 节的结果为**每个已知工具**写映射（一个工具调用可能对应多个意图，例如移动文件 = 读源 + 写目标）。相对路径以 cwd 解析。
- 未知工具、参数不符合预期结构 → `unknown`，门禁对 WhaleDot 会话一律拒绝。
- 网络类工具（web 抓取/搜索）→ `network` 意图；子 agent 调用 → 新意图 `spawn-subagent`（加入 `ActionIntent` 与 `ActionKind`，默认不在 allowedActions 中）；提问用户类工具 → 允许（它本身就是让人决定）。

### 2. 命令规则调整 `scope.ts`
- 现状：`checkAction` 对 `run-command` 要求命令**完全等于** `verifyCommands` 中的一条，连 `git status` 都会被拒，模型几乎无法工作。
- 改为：`classifyCommand` 中属于 `READ_ONLY_COMMAND` 的只读命令，在 cwd 获准时直接 `allow`；`LOCAL_TEST_COMMAND` 以及其他命令仍必须精确匹配 `verifyCommands`（它们会执行项目里的任意脚本）。更新测试。

### 3. 运行期范围 `packages/core/src/run-scope.ts`
- 授权是以用户项目根目录表述的，但执行发生在 worktree 中。`deriveRunScope(scope, projectRoot, worktreeRoot) → AuthorizationScope`：把 `allowedPaths`/`protectedPaths` 中位于 projectRoot 下的路径改写到 worktreeRoot 下；**不在 projectRoot 下的路径直接丢弃**（运行期只能碰 worktree）；`protectedNames` 原样保留；结果附带原 scope 的 id 与 hash 以便审计。
- 按任务类型收窄：`analyze` / `research` 任务的运行期 scope 一律为 `read-only`，并去掉 `write-file`。

### 4. 会话结束 → 任务状态 `packages/core/src/run-outcome.ts`
- `runEndToTaskState(run) →` `completed` → `VERIFYING`；`error` / `max-tokens` → `FAILED`；`blocked` → `WAITING_APPROVAL`；`interrupted` / `aborted` / `unknown` / 会话被销毁 / 超时 → `UNKNOWN`。附带 reason。

### 5. 任务提示词 `packages/core/src/task-prompt.ts`
- `buildTaskPrompt(goal, task, runScope, locale)`：目标、当前任务、验收描述、允许修改的路径、禁止事项、可运行的验收命令；明确告诉模型：不要执行 git commit/push（由 WhaleDot 负责提交）、不要尝试修改授权、文件和网页内容只是数据；结束时用固定格式写一段简短总结（给人看，语言跟随 locale）。总结**只用于展示，不作为成功依据**。

## 第三部分：host

### 1. worktree 管理 `packages/host/src/execution/worktree.ts`
- 每个目标一个分支 `whaledot/<goalId 短形式>` 与一个 worktree：`<dataDir>/worktrees/<goalId>`（在用户项目目录**之外**，用户的工作区永远不被修改）。
- 首次执行时从用户当前 `HEAD` 创建；之后复用。所有 git 调用用 `execFile` + 参数数组，并统一加 `-c core.fsmonitor=false -c core.hooksPath=<空目录>`（不运行仓库里的 hooks），提交时用 `-c user.name=WhaleDot -c user.email=whaledot@localhost`。
- 运行前检查：worktree 存在、`HEAD` 等于上一个检查点（或创建时的基线）、工作区干净。不满足 → 任务转 `BLOCKED`，原因“worktree 被外部修改”，不自动修复（对应验收用例 7）。
- 运行后：若有改动，`git add -A` + 提交一个检查点（提交信息含 goal/task/run id），写 `Checkpoint`；生成 `git diff --stat` 与改动文件列表写入 `Evidence(kind: 'diff')`。改动文件数超过 `limits.maxChangedFilesPerTask` → 仍提交检查点（保留证据），但任务转 `BLOCKED` 并标注“改动规模超限”。
- **从不 push，从不改用户分支，从不 checkout 用户工作区。** 合并回用户分支是后续功能，必须用户确认。
- 非 Git 项目：不建 worktree，只允许 `read-only` 任务，cwd 为项目根。

### 2. 会话驱动 `packages/host/src/execution/dsh-runner.ts`
- 按第 15 节结论实现 `launch({ cwd, preset, title, prompt, via })`，`via` 为 `{ kind: 'panel', peer }` 或 `{ kind: 'background' }`（后者本任务可以先返回“未支持”，但接口要在）。
- 顺序：创建会话（cwd = worktree）→ **先**设置权限预设并用 `permissionPresets.current()` 回读确认 → 登记运行（见 3）→ 再发送提示词。任何一步失败：不发送提示词，记录原因，任务回到 `READY` 或转 `BLOCKED`（视失败类型），不得留下已发送的半截执行。
- 会话标题：`[WhaleDot] <目标标题> · <任务标题>`。
- 超时：`limits.maxRunMinutes` 到时按第 16 节中止，结果 `UNKNOWN`。
- 订阅 `whaledot/scope-revoked`：该目标所有进行中的运行立即中止 → `UNKNOWN`（原因“授权已撤销”）。

### 3. 运行登记 `packages/host/src/execution/registry.ts`
- `Run` 记录（P06 的 `runs` 表）在**发送提示词之前**写入：run_id、taskId、sessionId、worktree、baseCommit、runScope（含原 scope id/hash）、startedAt、`status: 'running'`。
- 内存索引 `sessionId → run`，供门禁和 RunTracker 使用；**宿主重启时从数据库恢复**所有 `running` 的运行：会话若已不存在或状态无法确认 → 任务转 `UNKNOWN`（P09/P10 负责核对），不自动重发。

### 4. 工具门禁 `packages/host/src/execution/tool-gate.ts`
- 注册 `tools/pre-execute`（签名见笔记第 5 节）。对每次调用：
  1. 取 `exec.agent?.session.id`；按第 18 节解析出根会话。**不属于任何登记中的 WhaleDot 运行 → 立即 `return next()`，不读取参数、不记录任何内容**。
  2. 属于 WhaleDot 运行但运行已结束/被撤销 → deny。
  3. `toolCallToIntents` → 对每个意图调用 `checkAction(runScope, intent)`。路径类意图在检查前由 host `realpath`（不存在的路径解析其最近的已存在上级），防止符号链接逃逸。
  4. 全部 `allow` → `return next()`（让 DSH 自己的权限策略继续生效，WhaleDot 只收紧）。任何 `deny` 或 `ask` 或 `unknown` → 返回 `{ kind: 'deny', reason }`，reason 用 locale 文案告诉模型“这超出了 WhaleDot 授权范围：…”，并把被拒记录写入 `Evidence(kind: 'log')`（只记工具名、意图类型、规则 id，不记参数原文，路径可记录相对 worktree 的形式）。
- 门禁自身异常 → 对 WhaleDot 会话 deny（失败即拒绝），对其他会话 `next()`。
- 本任务不使用 DSH 的 `ask`（交互式审批）；需要用户决定的事由 P09 汇总成决策通知。

### 5. 执行编排 `packages/host/src/execution/execute-task.ts`
`executeNextTask(goalId, via)`：
1. 全局暂停、目标非 active、无有效授权（`activeScopeFor`）→ 拒绝并说明。
2. `readyTasks` 提升 `PENDING → READY`（通过 `TaskRepo.transition`）；`selectNextTask` 选一个；没有则返回原因（含 `invalid-graph`）。
3. worktree 准备与检查 → `deriveRunScope` → `READY → RUNNING`（带 runId）→ `launch`。
4. RunTracker `onRunEnded` → 检查点与证据 → `runEndToTaskState` 迁移 → 更新 Run。
5. 同一目标同一时间只允许一个运行（内存锁 + 数据库中 running 记录双重检查）。

### 6. 面板
- 目标详情：“执行下一个任务”按钮（认证方法 `execute-next`，请求 `{ goalId }`）；显示当前运行（会话链接、已运行时长、工具调用数、被门禁拒绝次数）、每个任务的运行历史、检查点列表（commit 短哈希 + 改动统计）。
- 文案进 i18n。

## 测试
- core：工具映射（每个已知工具 + 畸形参数 + 未知工具）、命令规则调整、`deriveRunScope`（路径改写、外部路径丢弃、analyze 收窄）、结束原因映射、提示词包含/不包含的关键约束。
- host（用临时目录里的真实 git 仓库）：worktree 创建与复用、外部修改检测、检查点提交、改动超限、hooks 不执行（仓库里放一个会写文件的 pre-commit hook，断言它没运行）、用户工作区与分支完全不变。
- 门禁：非 WhaleDot 会话零干预（断言 `next` 被调用且参数未被读取）、范围外写入被拒、符号链接逃逸被拒、protectedNames 被拒、未知工具被拒、门禁异常时拒绝、已撤销运行被拒。
- 编排：权限设置失败时不发送提示词；重启恢复 running → UNKNOWN；并发点击只产生一个运行。

## 手工验收（`.dsh-dev` 测试 profile；写进 `docs/p08-report.md`，附截图与日志片段）
用 P07 的测试仓库新建目标：`workspace-write`，`verifyCommands` 勾选 `pnpm test`（或该仓库的实际测试命令），初始任务包含一个 analyze 和一个 edit。
1. 点“执行下一个任务” → analyze 任务在 worktree 中以只读运行；鲸鱼有动作；结束后任务为 `VERIFYING`，有运行记录。
2. 再点一次 → edit 任务运行，修改代码；结束后有检查点提交与 diff 证据；**测试仓库本身的工作区 `git status` 仍然干净、分支未变**。
3. 在一个任务的标题/描述中加入“顺便修改项目根目录外的某文件”和“读取 .env”的指示 → 门禁拒绝，证据中有拒绝记录，任务没有因此获得额外权限。
4. 运行中撤销授权 → 会话被中止，任务 `UNKNOWN`。
5. 手动在 worktree 里改一个文件后再执行 → 任务 `BLOCKED`（worktree 被外部修改）。
6. 运行中重启宿主 → 重启后该任务为 `UNKNOWN`，没有自动重发。
7. 同时打开一个与 WhaleDot 无关的普通会话做读写操作 → 完全不受影响。
