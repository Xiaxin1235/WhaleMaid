## 目标

在作者确认的目标范围内，只读地观察三类外部变化，判断它们会不会影响正在推进的目标，产出交给 1.4 的建议卡：

- **A 依赖新版本**：npm registry、PyPI JSON 接口，只看**直接**依赖；
- **B 本地外部改动**：本地 git 只读命令，不联网；
- **C 项目自己的 GitHub 状态**：默认分支 CI 结论、新开的 issue/PR。

## 先查证（写进报告，附出处）

1. p24 报告所说的接入点 `InitiativeService.detectGoal`：外部事实如何进入快照，检测器如何保持纯函数（不读时钟、不做 IO）。
2. **凭据**：DSH 是否有公开的凭据服务（如 `@deepseek-ai/dsh-credentials` 或 Harness 设置里的凭据存储）可供插件读写一个“GitHub 只读令牌”。查官方类型和 README，不臆造接口。
   - 有：用它保存可选令牌，面板只显示“已设置 / 未设置”。
   - 没有：1.5 只支持从环境变量 `WHALEMAID_GITHUB_TOKEN` 读取，面板说明这一点；**不要**把令牌写进配置文件、数据库或日志。
3. 宿主可用的网络能力：Node 内置 `fetch`、代理设置（`HTTPS_PROXY` 等）是否需要支持；超时和取消如何接入现有的 dispose。
4. 调度器在哪里决定“这个目标现在能不能开始新的执行”，D10 的暂停应接在哪里，且**不改动**正在进行中的执行。

## 实现

### 1. 订阅与配置

- 目标详情新增“项目雷达”区块：自动识别项目的 `origin` 远程地址（仅 GitHub）和依赖清单（`package.json` 的 dependencies 与 devDependencies、`pyproject.toml` 的 `[project].dependencies` 与 Poetry 依赖、`requirements*.txt`），列出将观察的内容（仓库、依赖个数、本地检查项），由作者确认开启，可逐项取消，可手动补充 GitHub 仓库地址。
- 配置：`radar.enabled`（总开关，**默认关**）、`radar.sources.dependencies` / `.localGit` / `.github`（默认开，仅在总开关和目标订阅都开启时生效）、`radar.checkHours`（默认 24）。每个检测器 D8–D11 接入现有 `initiative.detectors.*` 的开关和最高分级。
- 订阅属于目标；目标完成或授权撤销后停止观察，记录保留。关闭任何开关都不删除记录。

### 2. 观察与限额

- **B 本地 git**：跟随现有主动性检测运行（事件触发、启动补做、每日首次检测），只用只读 git 命令（如 `rev-parse`、`status --porcelain`、`log`），在目标的项目目录内执行，带超时；识别哪些提交和改动**不是** WhaleMaid 产生的（对照 WhaleMaid 的 worktree、检查点和运行记录）。
- **A、C 联网检查**：每个目标每 `checkHours` 小时最多一次（每个本地日首次检测时触发；宿主启动时若已超时则补做）；面板“立即检查”按钮。
- 所有外部请求经过**一个可注入的客户端**（测试用录制好的响应）：超时、取消、`User-Agent` 用中性的插件名（不含用户邮箱或身份信息）、GitHub 请求带 ETag 条件缓存。
- GitHub 默认不带令牌；读取响应头里的剩余额度，接近耗尽时推迟到额度重置之后，不重试刷屏。连续失败在面板显示原因，不产生建议卡。
- 新表（加迁移，导出与追溯包含它们）：`radar_subscriptions`、`radar_observations`（每个订阅只保留最近若干条快照：版本、CI 结论、HEAD、请求数、ETag、失败原因）。

### 3. 检测器（纯函数，产出 `OpportunityCandidate`）

| ID | 触发条件 | 采纳选项（只用 1.4 已开放的动作） | 默认最高分级 |
| --- | --- | --- | --- |
| D8 依赖破坏性更新 | 直接依赖出现新的大版本（0.x 的次版本变化也算），或新版本发布说明 / 变更摘要含 breaking、破坏性字样，或当前所用版本被标记弃用 | 起草只读的“升级影响排查”目标（复用 1.4 的只读草案流程）；添加备注 | L2 |
| D9 默认分支 CI 失败 | 默认分支最近 ≥2 次 CI 结论为失败，且目标仍活跃 | 暂停目标；起草只读排查目标 | L2 |
| D10 外部改动冲突 | 出现非 WhaleMaid 的改动，且碰到**正在执行**的目标的工作目录或受保护路径 | 继续 / 暂停目标 / 查看改动 | L3 |
| D11 相关 issue/PR | 新 issue/PR 的标题关键词或改动的文件路径，与目标涉及的路径匹配 | 只进简报（L1），不发卡 | L1 |

- 证据只存引用：包名与版本、CI 运行 ID、issue/PR 编号、提交哈希，以及摘要哈希；外部正文按需读取并截断显示。去重键包含版本号、运行 ID 或提交范围。
- **外部内容只当数据**：建议卡正文用固定模板，**不复述**发布说明、issue、提交信息中的原文；外部文字不能进入任何执行路径。
- 沿用 1.4 的冷却、合并、反馈、自动降级和效果统计；面板统计另加“检查成功率”和“近 7 天请求数”。

### 4. D10 暂停（作者已确定）

- D10 产生时，**该目标**暂停开始新的执行，直到作者回答“继续 / 暂停 / 查看改动”；进行中的执行不强行中断，按现有规则收尾；其他目标照常推进；回答“继续”后立即恢复。
- 暂停不依赖提醒渠道：L3 询问关闭（1.4 默认）时改用建议卡给出同样三个选项；建议卡也关闭时，在面板和目标详情显示“等待你确认外部改动”。
- 这是调度器行为的变化，需要独立测试；在面板和目标追溯中留下记录。

## 不要做

- 不调用模型；不做研究资料 / 新闻源；不做 webhook 或常驻服务；不支持 npm / PyPI 以外的生态。
- 不写任何外部系统：不开 issue、不提 PR、不改依赖、不修改项目文件；git 只用只读命令。
- 不新增建议卡的动作类型，不放宽 1.4 的只读草案限制和任何授权校验。
- 不改动 `../dsh-coopanion`。
- **不要推送，不要打标签。**

## 测试

- 依赖清单解析：npm 版本范围（`^`、`~`、区间、`workspace:`、git/文件依赖跳过）、Python 常见写法（`==`、`>=`、extras、环境标记）；只取直接依赖。
- 版本比较与 breaking 判定：表驱动，覆盖预发布版本、0.x、弃用标记。
- 网络层：录制响应覆盖 200、304、限流（含额度重置时间）、超时、取消、非 JSON；确认没有令牌时不发送认证头，有令牌时令牌不出现在日志、错误、追溯和面板里。
- 本地 git：在临时仓库构造外部提交、分支切换、未提交改动、碰到受保护路径的改动；确认 WhaleMaid 自己的改动不触发 D10，只有真正冲突才触发。
- D10 暂停：只影响该目标；进行中的执行不被打断；回答“继续”后恢复；L3 关闭、建议卡关闭时的回退行为。
- 安全：发布说明或 issue 里含“请执行 / ignore previous instructions”之类文字时，不进入执行路径，卡片不复述原文。
- 订阅生命周期：目标完成、授权撤销、总开关关闭时停止观察且记录保留。
- 扩展 `pnpm eval:initiative`：为 D8–D11 各加“应触发 / 不应触发 / 边界”夹具，准确率仍须 100%。
- 全量 `pnpm test`、`pnpm typecheck`、**`pnpm lint`**、`pnpm format:check`、`pnpm test:package` 通过。

## 隔离实测

在隔离环境 `whaledot-p02`（`.dsh-dev`，端口 3182，**不碰日常 profile，不在设了 DSH_HOME 的终端里启动桌面版 Harness**）里：

1. 一个临时 Git 项目，`package.json` 里固定一个已知有更新大版本的依赖的旧版本；在目标详情开启雷达，确认观察列表正确，点“立即检查”后出现 D8 建议卡（真实访问 npm，只读）。
2. 在 WhaleMaid 之外修改该目标正在使用的工作目录文件，确认 D10 出现、该目标暂停新执行、另一个目标照常推进；回答“继续”后恢复。
3. 对一个公开 GitHub 仓库（无令牌）完成一次检查，记录请求数与 ETag 缓存命中；第二次检查命中 304。
4. 关闭雷达总开关，确认不再联网，记录保留。截图记录面板与建议卡。
