# C09 鲸鱼插件：安静模式（新消息只亮小信封，不弹框）

**前置**：`whaledot-local` 分支工作区干净，最新提交至少包含 `3e9ec2d fix: hide blank Harness drafts from the conversation lists`。若工作区不干净，先停下说明。先跑一遍 `npm test` 与 `npm run test:inbox-ui`，确认基线通过。

## 目标

用户开启“安静模式”后，新消息只体现在桌宠旁的**小信封计数**（`#attention`）上，不再主动弹出任何框。用户点信封、双击鲸鱼或打开菜单时，一切照常可用。默认**关闭**，关闭时行为与现在完全一致。

## 先查证（写进回报）

列出桌宠当前所有“主动弹出”的入口及触发条件，至少包括：

- 最终回复气泡：`web/pet.js` 的 `showNextReply` → `bubble`。
- 通知 / 提问 / 审批卡：`presentNextNotice` → `interaction`，由 `noticeQueue` 驱动，`message.notice` 入队。
- 大肥鱼邀请与反馈卡：`companionInvitation`、`companionFeedback`。
- 系统通知：`systemNotifications`。
- 稍后提醒：`reminders` / `reminderDelayMs`。
- 鲸鱼插件内答题（`inlineQuestions`）是否会自己弹出。

另外说明现有 `notifications: false` 关掉了哪些东西，以及为什么它不等于安静模式。按目前所见，它会连带禁用“稍后提醒”等信封里的功能。

## 实现

1. **设置**
   - 新增 `quietMode: Volatile<boolean>`，默认 `false`，走与 `notifications` 相同的偏好保存路径（`preference` 动作白名单、`savePreference`）。
   - 设置面板与右键菜单各加一个开关“安静模式（新消息只亮信封）”，中英文案进 `web/locale.js`；新版、经典两种界面风格都要显示正常。
2. **开启时**
   - 不弹最终回复气泡，不弹通知 / 提问 / 审批卡，不弹邀请 / 反馈卡，不发系统通知，“稍后提醒”到点也不弹。
   - 这些内容照常进入信封：计数正确、点开能看到并处理；已读回执逻辑不变。
   - 信封有新内容时只允许一个**不遮挡**的轻提示（例如信封计数轻跳一次）。减少动态效果时不跳。
   - 鲸鱼的情绪 / 状态表情照常变化。这是她自己的样子，不算弹框。
3. **不受影响**
   - 用户主动打开的面板（信封、聊天、阅读器、菜单）照常工作。
   - 用户自己发出消息后，当前聊天面板里显示回复照常（面板本来就开着，不算主动弹出）。
4. **从开到关**
   - 开着时积压的内容**不补弹**，只留在信封里。
   - 关闭后，新到的内容按原逻辑弹出。
5. 快照与 tray 菜单如有“免打扰”类显示，与安静模式状态保持一致。不改 WhaleDot 侧的通知投递策略。

## 测试

- 单元 / 展示测试：
  - 开启时 `showNextReply`、`presentNextNotice`、系统通知、提醒均不弹，信封计数正确增加。
  - 关闭时与现在一致。
  - 从开到关不补弹积压内容。
  - 设置项能保存，重启后仍生效。
  - 两种界面风格下文案都显示正常。
- `test:inbox-ui` 补充一个场景：安静模式下来一条回复和一个提问，界面上没有 `bubble` / `interaction` 可见，`#attention` 显示 2，点开能处理。
- `npm test`、`npm run test:inbox-ui` 全部通过。
