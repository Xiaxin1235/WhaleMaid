# C11 鲸鱼插件：识别已归档的对话

**前置**：`whaledot-local` 分支工作区干净，最新提交至少包含 `c97ad54 chore: allow DSH 0.2.1-rc.3 hosts`。若工作区不干净，先停下说明。先跑一遍 `npm test` 与 `npm run test:inbox-ui`，确认基线通过。

**执行环境**：本任务要写 `D:\dsh_plugins\dsh-coopanion`，报告和证据写在 `D:\dsh_plugins\WhaleDot`，还要能运行 Git、Chromium 和 Electron。会话必须在开始时就具备这些权限；发现做不到，立即停下说明，不要只写一半代码。

**宿主版本**：本机 DSH Desktop 已是 **0.2.1-rc.3**。查证以 rc.3 为准；与 rc.2 不同的地方写进报告。

## 问题

WhaleDot P16 会把以往的大肥鱼对话归档，让 Harness 侧栏只保留当前那一条。归档用的是 DSH 的 `workspaceRegistry.archiveSession`，它可以撤销，不删除任何数据。

但桌宠恢复会话列表用的是 `sessionController.list`，这个接口**不过滤已归档会话**，于是出现两个问题：

1. 桌宠的“大肥鱼（旧对话）”和普通会话列表里，仍然列着已归档的会话。
2. 在桌宠里选中已归档会话并发消息，宿主的 archived-session-gate 会在模型步骤前直接拒绝。界面上既没有回复，也没有任何说明。

WhaleDot 的查证结论（`D:\dsh_plugins\WhaleDot\docs\dsh-api-notes.md` 第 30 节“P16 补充”）：

- `workspaceRegistry.archivedSessionIds` 是全局的已归档集合；
- `unarchiveSession` 可以恢复；
- Harness 侧栏默认不显示已归档会话。

## 先查证（写进回报，附 rc.3 类型或实现的出处）

1. 鲸鱼插件的宿主端能否通过 `ctx.inject` 拿到 `workspaceRegistry`？怎样读取已归档集合？集合变化时有没有事件或可订阅的状态？没有的话，给出最小的轮询或刷新时机。
2. 已归档会话发消息被拒绝时，桌宠收到的是什么：`sessionController.prompt` 的返回值或报错、会话事件。据此判断能否给用户明确的失败原因。
3. 鲸鱼插件是否有权限调用 `unarchiveSession`。**本任务不调用它**：恢复归档仍由 WhaleDot 面板或 Harness 完成。这一项只需查清并写进报告。

## 实现

1. **模型**：`PetSession` 增加 `archived?: boolean`。宿主端读取已归档集合并在快照中标记，集合变化时刷新。
2. **列表**：
   - 会话列表和托盘菜单默认**不显示**已归档会话。当前选中的会话除外：如果它被归档了，仍然显示，并标为“已归档”。
   - “大肥鱼（旧对话）”同理，已归档的不显示。
   - 不新增“显示已归档”开关。
3. **当前选中的会话被归档时**：
   - 聊天面板的输入框禁用，并提示“这段对话已归档，可以在 WhaleDot 面板或 Harness 里恢复后再继续”；中英文案放 locale。
   - 双击默认目标是“和大肥鱼聊天”时，自动指向当前大肥鱼会话（`snapshot.companionSessionId`），不指向已归档的旧会话。
4. **发送被拒绝时的兜底**：如果查证 2 表明拒绝能被识别，发送失败要显示明确原因（已归档），不能停在“已发送”，也不能静默。
5. **信封和未读**：已归档会话里还没读的回复，仍保留在信封里可以阅读，只是不能从信封“继续对话”。已读、回执逻辑不变。
6. **顺手修**：`tests/figures.test.ts` 的 “serves the frame with an opaque-origin CSP…” 和 `tests/inbox-receipts.test.js` 的 “serializes atomic receipts…”，在默认并发下会稳定超过 5 秒。只给这两个用例单独设 20 秒时限，不改断言。

## 测试

- **模型**：
  - 已归档会话标记 `archived`；
  - 当前会话被归档时仍显示并标注；
  - 恢复归档后标记消失；
  - 大肥鱼角色名不受影响。
- **展示**：
  - 列表和托盘不显示已归档会话（当前选中的除外）；
  - 聊天输入禁用并显示说明；
  - 双击默认目标不会落到已归档会话。
- **发送**：被拒绝时显示明确原因，按查证 2 能识别的程度测试。
- `npm test`（默认并发，两处超时已修好）、`npm run test:inbox-ui`、`npm run test:desktop` 全部通过。
