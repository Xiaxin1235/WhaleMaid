# P13B 决策卡增加“放弃目标”与“改方向”（P13 补充）

**时机**：P13 第零部分和正文完成、提交之后再做这一部分，单独提交。若 P13 还没做完，先做完 P13，不要把两部分混在一个提交里。

## 背景

P12 第二部分的项目经验起草监听了“用户在决策里选择放弃 / 改方向”这个触发（`lessonTrigger` 的 `decision` 分支、`drafts.ts` 里的 `hasDecision`），但现有决策选项 `DecisionChoiceSchema`（`packages/core/src/verify/model.ts`）只有 `retry`、`accept`、`rollback`、`pause-goal`、`view-diff`、`verify`、`resume-goal`，**没有** `abandon` 和 `change-direction`，所以这条触发目前永远不会发生。本任务给**用户**的决策卡加上这两个按钮。

边界：

- 这是给用户本人点的按钮。**大肥鱼不能提议、更不能执行这两个动作**，P13 的“不做”清单保持不变：用户让她放弃目标或改方向时，她说明做不到，并指向决策卡上的对应按钮。
- 不删除任何数据。放弃 = 目标进入已有的 `cancelled` 状态，历史、任务、验收、事件全部保留。
- 不扩大任何授权范围；改方向只改变下一轮规划的输入，不改授权路径、权限和验收命令。

## 第一部分：查证（写进报告）

1. `GoalStatusSchema` 已有 `cancelled`。确认目标 / 任务状态机里从 `active`、`paused` 到 `cancelled` 的合法转移；正在执行的任务如何安全中止（复用现有暂停 / 中止执行的路径，不新写一套）；`cancelled` 目标在调度器、面板、P10 导出、伙伴工具 `goals_overview` 中如何显示，是否需要补文案。
2. 决策的数据流：`DecisionChoiceSchema` → 通知的 `choices` → 面板决策卡与 P05 智能选项 / 信封作答 → `notificationChoices` 记录（`action`、`result` 字段的确切取值）。确认新增两个枚举值对已存数据和 P05 旧通知没有影响（旧通知的 `choices` 不含新值，照常显示）。
3. 规划器如何读取 `user_notes`，以及“改方向”后让下一轮规划立即使用新方向的最小做法（例如：当前等待决策的任务按现有状态机结束为不再继续的状态，目标保持 / 恢复 `active`，下一轮规划带上新备注）。写清楚选择了哪种做法以及原因。

## 第二部分：实现

### 1. 选项

- `DecisionChoiceSchema` 增加 `abandon`、`change-direction`。它们出现在**需要用户决定的目标级决策**里：连续 UNKNOWN、停滞、执行停下需要用户处理（`execution-needs-owner` 一类）。其他通知不加。
- 中英文案：
  - “放弃这个目标” / “Abandon this goal”。
  - “改方向” / “Change direction”。
  - 说明文字写清后果：放弃后不再自动推进，记录保留；改方向会把你写的新方向作为备注交给下一轮规划。

### 2. 放弃

- **面板**：点击后二次确认，确认框写明目标标题和“记录会保留，不能自动恢复推进”。
- **信封 / 原生答题**：不直接执行放弃。选这一项只提示“请到 WhaleDot 面板确认放弃”，并打开面板；或者干脆不在信封里提供这一项。二选一，写进报告。
- **执行时**：
  - 重新读取目标最新状态并校验版本，状态已变就放弃执行。
  - 依次：中止正在执行的任务（复用现有路径）、关闭自动推进、目标进入 `cancelled`、该目标未结算的通知全部结算。
  - 写一条 autopilot 事件，`actor: 'user'`，记录决策 id。
  - `notificationChoices` 记录为 `action: 'abandon'`、成功结果。

### 3. 改方向

- **面板与信封都提供**，都要求用户填写新方向（≤500 字，必填）。
  - 经 `redactSecrets` / 记忆同款秘密检查，含密钥拒绝。
  - 信封里用自定义文字作答即是新方向；没写文字就不执行。
- **执行时**：
  - 写入 `user_notes`。来源标为决策，沿用 P13 第一部分查证 2 的可空 `notificationId` 改法，或直接挂在这条决策通知上，与 P13 保持一致。
  - 按查证 3 的做法结束当前等待中的任务，并让目标继续推进（自动推进原来是开就保持开，原来是关就保持关）。
  - 写事件；`notificationChoices` 记录为 `action: 'change-direction'`、成功结果。
- 确认文字写明：“新方向会出现在之后每一轮任务的提示词里”。

### 4. 与项目经验联动

- 两个动作成功后，P12 的 `decision` 触发应自然生效（受“起草项目经验”开关控制，默认关）。
- 起草事实里加上决策类型，以及改方向时用户写的新方向（已脱敏）。仍不含会话原文。

### 5. 大肥鱼

- 人设与 P13 拒绝清单补一句：放弃目标和改方向只能由用户在决策卡上操作。
- `pending_decisions` 工具返回的选项里包含这两个新选项的名称，便于她指路。她不能代为选择。
