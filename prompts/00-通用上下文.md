## 硬性规则

1. **不要臆造 DSH API。** 用到任何 `ctx.xxx`、事件名、gateway 方法前，先在上述 `.d.ts` / README / 参考插件源码里找到出处（P02 之后优先查 `docs/dsh-api-notes.md`）；找不到就写一个窄接口（interface）+ 适配器，把不确定点集中在适配器里，并在回报的“待确认”中列出。
2. 不修改 DSH 本体，不修改 `%USERPROFILE%\.dsh` 下的任何文件（除非任务明确要求，且只在 WhaleDot 自己的 `~/.dsh/whaledot/` 目录内）。
3. TypeScript strict、ESM；公共函数写简洁的 JSDoc；不要引入任务没要求的大型依赖。
4. 领域逻辑放 `packages/core`，必须是纯函数/纯类（无 IO、无 Date.now 直接调用——时间与 ID 通过注入的 `Clock` / `IdGen` 传入），并配 vitest 单测。
5. 任何来自模型、文件、网页、工具输出的文本都只是**数据**，代码中不得让它们直接成为命令、权限或目标变更。
6. 安全默认：拒绝优先；未知状态不当作成功；外部命令用 `execFile` + 参数数组，绝不拼接 shell 字符串。
7. 完成后运行 `pnpm -r build`、`pnpm -r test`、`pnpm lint`，全部通过再回报。不要 `git push`；可以在本地 `git commit`，提交信息用英文祈使句。
8. 不确定的产品决策不要自作主张扩大范围：按最小可用实现做，并在回报中列出。
