# C01 鲸鱼插件：开场白气泡 + 在小信封里直接作答

两个改动，都是为了让 WhaleDot 和日常对话用起来更顺手。分两个提交。

## 背景

- 用户在全局 `~/.dsh/AGENTS.md` 中加了“开场白”指令：模型每条最终回复以一两句第一人称、活泼的开场白开头（≤ 80 字），空一行后才是完整回答（模板见 `D:\dsh_plugins\WhaleDot\templates\AGENTS.whale-brief.md`）。
- WhaleDot 通过 `ctx.userQuestions.ask` 发出决策提问（带 2–4 个选项和说明）。0.4.13 的小信封只提供“去处理”入口，用户必须回到 Harness 才能作答（见 WhaleDot `docs/p04-p05-report.md`）。

## 第一部分：气泡优先显示开场白

现状：`web/speech.js` 的 `replyPreview(text, limit = 180)` 超过 180 字时按句子截断，`web/pet.js` 用它生成气泡文字。

改为：
1. 若回复的**第一段**（从开头到第一个空行，去掉首尾空白）满足：不超过 120 个字符（Unicode 字符计）、不是代码块/表格/列表/标题，且回复还有后续内容 → 气泡只显示第一段，`long: true`（保留“展开全文”）。
2. 否则保持原有截断行为不变。
3. 新增设置项「回复气泡：优先显示开头一段」（默认**开启**；关闭后完全等同 0.4.13 行为），中英文案。
4. 测试：纯函数单测覆盖——有开场白的长回复、短回复（不分段）、第一段是代码块/列表、第一段过长、只有一段、CRLF 换行、emoji 与中文混排计数；`npm run test:inbox-ui` 通过。
5. 同步 `docs/usage.md` 与 `docs/text-readability-contract.md` 中关于回复预览的描述。
6. 提交：`feat: prefer the opening paragraph in reply bubbles`。

## 第二部分：在小信封里直接回答提问

### 先查证（写进 WhaleDot 的 `docs/dsh-api-notes.md` 新增第 20 节，结论 + 出处）
- `@deepseek-ai/dsh-user-questions` 0.2.1-rc.2：一个待回答的提问，**除了 Harness 自己的界面之外，插件能否提交答案**？查清答案提交的机制——是通过 `user-questions/request` waterfall 中某个处理者返回答案、某个 answer/resolve 方法，还是 session controller 的某个方法；多个界面同时存在时以谁为准、重复提交会怎样。
- dsh-coopanion 现在如何监听提问（`src/index.ts` 中对 `userQuestions` 的使用）、信封条目从哪里来（`src/notification-broker.ts`），以及渲染页如何显示信封（`web/pet.js`、`web/notification-ui.js`）。
- 若查证结论是“插件无法安全地提交答案”，**停下**，只交付第一部分，并在回报中说明原因与可行替代方案。

### 实现（查证可行时）
1. 信封里的“提问”条目展开后显示：问题、`detail`、每个选项（label + description），单选按钮；若原问题允许“其他”，显示一个可选文本框；“提交”与“去 Harness 处理”两个按钮。
2. 提交路径：渲染页 → `pet:action`（新 action 类型，严格校验字段与长度）→ 主进程 → host（新 IPC 消息类型）→ 用查证到的方式提交答案。
   - host 端必须校验：该提问仍处于待回答状态、提问 id 与选项 label 完全匹配（不能提交原问题中不存在的选项）、同一提问只提交一次。
   - 提交成功或该提问已在别处被回答 → 信封条目按现有“已处理”规则结算；失败 → 显示简短错误并保留“去 Harness 处理”。
3. **审批（approval）不在本次范围**：审批仍只通过“去处理”在 Harness 中完成（审批涉及权限，保持原有路径）。
4. 多选题、带 `intent: 'plan-review'` 的提问：本次只显示“去 Harness 处理”，不做内联作答。
5. 新增设置项「在小信封里直接回答提问」（默认开启），关闭后等同 0.4.13。
6. 测试：host 侧校验（过期、重复提交、伪造选项、已在别处回答）；`npm run test:inbox-ui` 增加内联作答用例；`npm test` 全部通过。
7. 同步 `docs/usage.md` 与 `docs/notification-contract.md`。
8. 提交：`feat: answer questions inline from the inbox`。

## 验收
1. 在 WhaleDot 隔离测试 profile 中用 `link:` 安装本分支构建产物（测试鲸鱼使用独立数据目录）。
2. 普通对话：回复带开场白时，气泡只显示开场白，可展开全文；关闭设置后恢复截断行为。
3. WhaleDot 决策：制造一个 `not-scorable` 决策 → 信封中直接点选“再试一次” → WhaleDot 面板显示该通知已处理、来源为 inbox，任务进入 READY。
4. 同一提问在信封与 Harness 中几乎同时作答 → 只生效一次，另一边正确显示已处理。
5. 普通会话里模型发起的 `ask_user_question` 也能在信封中作答，结果与在 Harness 中作答一致。
6. 请用户目视确认：气泡文字、信封中的选项与说明、提交后的结算效果（截图或描述）。

## 不做
- 会话归档、响应式表情（后续 C02、C03）；不改审批流程；不改角色素材。
