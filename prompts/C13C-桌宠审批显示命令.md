# C13C 鲸鱼插件：桌宠审批显示实际要运行的命令

**前置**：`D:\dsh_plugins\dsh-coopanion` 的 `whaledot-local` 分支工作区干净，包含 `876ce93`（C13B）。先跑 `npm test` 和 `npm run test:inbox-ui`，确认基线通过。若工作区不干净，先停下说明。

**执行环境**：本任务要写 `D:\dsh_plugins\dsh-coopanion`，报告和证据写在 `D:\dsh_plugins\WhaleDot`，还要能运行 Git、Chromium 和 Electron。会话必须在开始时就具备这些权限；做不到，立即停下说明。宿主为 DSH Desktop **0.2.1-rc.3**。

## 问题

C13B 之后，审批能在桌宠信封里回答，但在普通会话中，桌宠只显示审批的“原因”。这个原因是**模型自己写的**提权理由，例如 “C13B allow-once acceptance”，看不到实际要运行的命令。Harness 的审批卡会附上工具详情，桌宠没有。用户在桌宠里点“允许一次”，依据的只是模型的自述，这不安全。

原因是 C13B 提示词要求“不下发工具参数”。这一条对审批来说过严，本任务放宽为：**只下发命令文字**。

## 要求

### 宿主端

- 对 `toolName` 为 `bash` 或 `pwsh` 的审批，按审批的 `callId` 找到对应的 `tool/call` 事件，解析其 `arguments` JSON，取出 `command` 字段，可选再取 `workdir`。
  - `src/notification-broker.ts` 已经处理会话事件，`src/index.ts:314` 一带已有按 `callId` 查找 `tool/call` 的写法，可以参照。
  - 只用公开的会话事件，不读取其他来源。
- 显示前处理：
  - **脱敏**：隐去疑似密钥和令牌（`sk-`、`ghp_`、`gho_`、`github_pat_`、`AKIA`、`Bearer xxx`、`xoxb-` 等常见格式），以及形如 `NAME=value`、`$env:NAME = value` 的环境变量赋值中的值。仓库里若已有脱敏函数就复用；没有就在宿主端新写一个小函数，并补测试。
  - 去掉控制字符，保留换行，最多 12 行。
  - 截断到 500 个字符；超出时末尾加“…（已截断）”。
- 只下发脱敏、截断后的命令文字（和 `workdir`），**仍然不下发**其他参数，例如 `description`、`justification`、超时、沙箱字段。
- 找不到对应调用、参数无法解析、没有 `command` 字段时，不显示命令，并在信封里标注“未能取得命令，请在 Harness 查看”。这种情况下**“允许一次”按钮禁用**，只保留“拒绝”和“去 Harness 查看”。
- 其他工具的审批（非 `bash` / `pwsh`）维持现状，显示原因；并在原因下注明“详情请在 Harness 查看”。

### 桌宠界面（两种界面风格都要做）

- 审批卡片的顺序：
  1. 标题“需要批准”；
  2. **要运行的命令**：等宽字体，单独成块；`workdir` 有值时，在下面小字显示“在 <目录> 中运行”；
  3. 模型给出的理由：降为次要文字，前面加标签“模型说明：”，让用户分清哪部分是模型自己写的；
  4. 按钮。
- 命令块可以横向滚动或自动换行，不能撑破信封。
- 防误触规则不变：“允许一次”不是默认焦点；打开 1 秒后才可点；回车不触发允许。
- 中英文文案都要有。

### 文档

`docs/usage.md` 和 `docs/session-chat-contract.md` 说明：

- 桌宠审批会显示要运行的命令（已脱敏、截断）；
- 取不到命令时不能在桌宠里允许；
- 模型说明只作参考。
