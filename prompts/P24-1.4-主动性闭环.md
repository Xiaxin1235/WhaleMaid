# P24 WhaleMaid 1.4：主动性闭环（I2 建议卡、反馈与效果评测）

**前置**：`master` 与 GitHub 同步（当前发布 1.3.1），工作区干净（本提示词除外）。先跑 `pnpm install --frozen-lockfile`、`pnpm build`、`pnpm test`，确认基线通过。

> **改名说明**：项目已从 WhaleDot 改名为 WhaleMaid（包名 `dsh-whalemaid`、`@whalemaid/core`）。以下内容**有意保持旧名**，不要改：本地目录 `D:\dsh_plugins\WhaleDot`、插件配置 ID 和数据目录 `whaledot`、大肥鱼预设 `whaledot-companion`、隔离 profile `whaledot-p02`。

**必读**：[docs/主动性引擎设计.md](../docs/主动性引擎设计.md)（第 6–10 节是本任务的主要依据）、[docs/i1-report.md](../docs/i1-report.md)、[docs/p21-report.md](../docs/p21-report.md)。

## 目标

I1 已经能**发现**问题，但只放在面板和简报里。1.4 要把它变成闭环：

**发现 → 判断价值 → 建议卡给出选项 → 你确认 → 走现有通道执行 → 追踪结果 → 根据反馈调整**。

同时落地**主动性效果评测**：衡量的不是“提了多少建议”，而是建议有没有用、有没有打扰你。

## 先查证（写进报告，附代码出处）

1. `InitiativeService.available()` 目前强制关闭 `cards` 和 `asks`；`INITIATIVE_NOTIFICATION_KIND = 'initiative'` 只是预留。确认放开后需要改的所有位置。
2. P21 的可靠投递（`NotificationDeliverer`、`decision-lifecycle.ts`、`decideDelivery` 的 `decisionDelivery` 状态、重试、恢复、换代）能否直接承载 `initiative` 类型的通知；哪些逻辑只对 `decision`/`blocked` 生效（如 `isDecision`），需要怎样扩展而不改变现有决策通知的行为。
3. `CompanionActions.propose` 与 `CompanionActionSchema` 现有的动作（`draft-goal`、`start-work`、`goal-pause`、`autopilot`、`global-pause`、`goal-note`）各自的确认方式与权限边界；从建议卡采纳时，复用哪条路径才能保证“不扩权”。
4. 面板“主动性”卡片、通知中心、桌宠信封（DSH 原生提问）三处如何展示同一张建议卡，以及现有选项结算（只结算一次、旧选项作废）的复用方式。

查证结果与设计文档不一致时，以代码为准，在报告里列出差异和处理方式。

## 实现

### 1. 建议卡（L2）与询问（L3）

- 放开 `cards`、`asks` 两个渠道，接入 `initiative` 通知类型，走 `decideDelivery` 与 P21 的可靠投递（勿扰、静音、每小时上限、重试、重启恢复都要生效）。
- **分级限制**（设计文档第 7 节）：L2 同一目标两张卡至少间隔 4 小时，间隔内的新机会合并进下一张；L3 不限次数但同一件事不重复问，勿扰时段暂存。冷却期 7 天。参数放进 `initiative.limits.*`，面板可调。
- **合并**：同一目标同一次检测产生的多条机会合并为一张卡，按得分排序。
- **默认值（作者已确定）**：`channels.cards`（L2 建议卡）**默认开启**；`channels.asks`（L3 询问）默认关闭。从旧版升级的用户同样生效（除非他们在设置里显式关过），所以 1.4 的欢迎页更新要点要说明“现在会主动给建议卡，在哪里关”，“主动性”卡片顶部也放一键关闭的入口。设计文档第 10 节的默认值表同步修改。

### 2. 卡片选项：只映射到已有动作

每张卡最多 2 个“采纳”选项 + 固定的 **稍后**（选择时间）、**忽略**、**不再提醒这类事**（只对当前目标生效，面板可恢复），以及“查看证据”。

| 检测器 | 采纳选项（只从已有动作中选） |
| --- | --- |
| repeatedFailure | ① 起草一个**只读排查**目标（`draft-goal`：只读预设、只做环境/依赖/数据检查，**仍须在面板审核并确认授权**，不自动开启自动推进）② 暂停目标（`goal-pause`） |
| stallWarning | ① 给目标加备注提醒自己拆分任务（`goal-note`）② 暂停目标 |
| noAcceptance | ① 打开目标详情去补充验收命令（只导航，补充仍走面板重新审核授权） |
| budgetBurn（L3） | ① 暂停目标 ② 打开目标详情（追加预算仍须在面板确认） |
| pendingBacklog | ① 打开待处理的决策卡 |
| idleGoal | ① 暂停到指定日期或保持现状（用 `goal-pause` / 备注实现，不自动放弃） |
| leftovers | ① 起草后续目标（`draft-goal`，仍走审核） |

- 采纳时复用现有结算：先持久认领、校验目标版本与授权仍有效，再执行；面板与桌宠同时提交只执行一次；过期或伪造的选项被拒绝。
- **绝不**：自动开启自动推进、追加预算、扩大授权范围、替你在决策卡上选择、开启高权限模式。

### 3. 结果追踪与学习

- `opportunities` 记录状态流转：`delivered → accepted / snoozed / dismissed / muted / expired`，以及 `outcomeAt`。
- **采纳后效果**：采纳后 48 小时内，相关目标出现新的 PASS 或状态推进，记为“带来进展”；若采纳的是只读排查目标，以该目标完成为准。
- **自动降级**（只做可解释、可撤销的调整）：某检测器近 30 天投递 ≥10 次且无效打扰率 > 50%，其默认分级降一级；采纳率很低时阈值在规定范围内上调。每次调整写追溯记录，面板可一键恢复。
- **大肥鱼的经历**（设计文档 I3 的一部分，不调用模型）：被采纳且带来进展的发现，用固定模板写入 `companion_journal`，可追溯到原始记录；开关 `initiative.companion.journal`，默认开。收工汇报**不在本次范围**。

### 4. 主动性效果评测

- **面板指标**（近 7 / 30 天，按检测器）：投递数、采纳率、无效打扰率（忽略 + 不再提醒 + 无回应）÷ 投递、采纳后带来进展的比例、误触发反馈数（卡片上加一个“这条不准”，计入误触发率）、模型调用成本（本版本恒为 0）。
- **离线评测脚本**：新增 `pnpm eval:initiative`，用一组固定的场景夹具（至少覆盖 7 个检测器各自的“应触发 / 不应触发 / 边界”，以及多目标同时出问题、勿扰时段、用户连续忽略等）回放检测、分级、合并、限流和自动降级，输出触发准确率、打扰次数和各指标的汇总表。结果写进报告，作为以后调整阈值的基线。

### 5. 配置、面板与文案

- 面板“主动性”卡片：新增建议卡开关说明、`limits` 参数、每个检测器的指标与“恢复默认”、被静默的检测器列表（可恢复）。
- 中英文文案齐全。卡片正文用固定模板，**不调用模型**。

## 测试

- `resolveLevel` 与新的限流、合并：表驱动覆盖渠道开关、检测器上限、L2 间隔、L3 勿扰暂存、冷却期、合并后的排序。
- 投递：与现有决策通知共用每小时上限时总量不超限；重试、重启恢复、静音解除后重新提问对 `initiative` 同样生效；P21 的现有测试全部保持通过。

- 反馈与学习：构造 10 次投递 2 次采纳的序列，确认自动降级与追溯记录，面板可恢复；“不再提醒这类事”只影响当前目标。

- 离线评测脚本在 CI 中运行并对关键指标设下限（例如场景夹具上的触发准确率 100%）。

## 隔离实测

在隔离环境 `whaledot-p02`（`.dsh-dev`，端口 3182，**不碰日常 profile，不在设了 DSH_HOME 的终端里启动桌面版 Harness**）里：

1. 不改任何设置（确认建议卡默认开启）；用一个会因同一原因反复失败的验收命令触发 `repeatedFailure`，确认桌宠信封和通知中心出现建议卡，选项正确。
2. 选“起草只读排查目标”，确认生成的是需要你在面板审核授权的草案，没有自动执行。
3. 再触发一次，选“稍后”，到时间后重新出现；选“不再提醒这类事”后同一目标不再出现，面板可恢复。
4. 勿扰时段内触发，确认暂存并在结束后投递。
5. 面板查看指标与评测结果；截图记录。
