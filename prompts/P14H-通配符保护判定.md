# P14H 高权限模式：通配符只在字面指向保护项时拒绝（小修正）

**前置**：`master` 工作区干净，最新提交至少包含 `67263a5 fix: classify remaining trusted command gaps`。若工作区不干净，先停下说明。先读 `docs/p14g-report.md`、`packages/core/src/trusted-command.ts`（`overlap` 与 `protectedPattern` 判定）以及现有 `trusted-command-*.test.ts`。

## 问题

trusted 授权下，命令文字里的通配符只要和保护项**理论上有交集**就直接 `deny`。默认保护名称含 `id_rsa*`、`id_ed25519*`，它们和任何 `*.xx` 都有交集（例如可能存在 `id_rsa.ts`）。于是在默认授权下，下面这些日常命令全部被拒绝，连审批都不弹：

- `npx prettier --write "src/*.ts"`
- `npx eslint src/*.js`
- `git add *.md`
- `Get-ChildItem *.log`
- `copy *.txt out`

这是审查方在 P14G 提示词里“可能命中就 deny”的写法造成的，现在改成下面的规则。

## 新规则

用户决定：通配符只有**字面指向**保护项时才 deny；只是理论上有交集的，不因保护规则拒绝。命令本身的危险类别（删除、动态执行等）照常按 P14F/P14G 的规则 ask 或 deny，与本规则无关。

### 1. 文件名层（`protectedNames`）

对通配路径的最后一段 G 与每个保护名称 P，同时满足以下两条时 deny：

- G 与 P 有交集（沿用 `overlap`）；
- G 与 P 在**同一侧有非空的字面锚点**：
  - **开头**：G 开头的字面部分（第一个通配符之前）与 P 开头的字面部分都非空，且其中一个是另一个的前缀；
  - **结尾**：G 结尾的字面部分（最后一个通配符之后）与 P 结尾的字面部分都非空，且其中一个是另一个的后缀；
  - 比较不区分大小写。

例：

| G            | 命中的 P              | 结果              |
| ------------ | --------------------- | ----------------- |
| `*.key`      | `*.key`               | deny（结尾锚点）  |
| `secret*.key`| `*.key`               | deny              |
| `.env*`      | `.env`、`.env.*`      | deny（开头锚点）  |
| `id_rsa*`    | `id_rsa*`             | deny              |
| `*.ts`       | `id_rsa*`             | 放行（无同侧锚点）|
| `*.md`、`*.log`、`*.txt` | 默认名单 | 放行          |
| `*`          | 任意                  | 放行              |

### 2. 目录层（`protectedPaths`）

把通配路径解析到第一个含通配符的段之前，得到**字面目录前缀** D。以下任一成立则 deny：

- D 在某个保护目录之内，或等于它。例：`secrets/*`、`C:/proj/secrets/*.txt`。
- 通配段与保护目录的对应段按第 1 条的规则有字面锚点。例：保护 `C:/proj/secrets` 时，`sec*/*` 应 deny，`*/*.txt` 放行。
- 路径含递归 `**`，且 D 之下包含保护目录。例：保护 `C:/proj/src/secrets` 时，`src/**/*.ts` 一定会遍历进去，deny。保护 `C:/proj/secrets` 时，`src/**/*.ts` 放行。

### 3. 不变的部分

- 不含通配符的字面路径命中保护项照常 deny。
- 文件工具（read/write/edit/glob/grep）的保护规则完全不变。
- confirmed 模式完全不变。
- 默认保护名单不改。
- 删除类命令即使通配符放行，仍按类别 ask。例如 `del /q /s *.tmp` 在默认授权下应变为 ask / delete、recursive-delete，不再 deny。
