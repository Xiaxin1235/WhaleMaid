# P18 发布准备：文档、许可边界与包信息（M5 第一步）

**前置**：`master` 工作区干净，最新提交至少包含 P17 的提交 `feat: companion gives a daily progress brief`。若工作区不干净，先停下说明。

本任务**只整理，不发布**：

- 不推送；
- 不发布 npm 包；
- 不打 tag；
- 不修改版本号（保持 `0.0.0`），版本号和发布时间由用户决定。

## 背景

WhaleDot（MIT）已经做完自动推进闭环、通知、大肥鱼（记忆、回顾、提议、简报）和高权限执行模式，但：

- `README.md` 开头仍写着“独立验收和自动推进闭环尚未实现”，各功能说明是按任务零散追加的；
- 用户文档分散在 `README.md`、`docs/usage.md`、各 `pXX-report.md` 里；
- 没有检查过 WhaleDot 仓库里有没有混入鲸鱼插件（AGPL）的代码或素材；
- 包信息（描述、仓库地址、`files` 字段、许可证文件）没有核对过。

## 第一部分：许可边界检查（写进 `docs/p18-report.md`）

1. 扫描仓库中所有被 Git 跟踪的文件，确认没有来自 `@takboo/dsh-coopanion` 的代码、图片、角色包、音效或文案。比对方式由你设计，例如按文件哈希、特征字符串、图片资源。结论写清楚范围和方法。
2. `docs/coopanion/` 下的报告是 WhaleDot 自己写的说明文档，可以保留。确认其中没有大段复制 AGPL 源码。超过 15 行的连续代码引用要改成文字描述加出处。
3. 确认 `package.json` 的依赖中没有 `@takboo/dsh-coopanion`。WhaleDot 只通过 DSH 公开服务与它协作。
4. 新增 `scripts/check-license-boundary.mjs`：做第 1、3 项中能自动化的检查，并加入 `pnpm lint` 或单独的 `pnpm check:license`。

## 第二部分：文档整理

1. **`README.md`** 重写为面向用户的首页：
   - 一句话介绍；
   - 当前能做什么：目标与授权、自动推进与独立验收、通知与决策、大肥鱼、高权限模式；
   - 安全边界，例如：授权范围、确认机制、高权限的风险、记忆和回顾不授予权限；
   - 安装：链接到 `docs/日常安装与自查.md`；
   - 与鲸鱼插件的关系和许可说明；
   - 开发入口。
   
   各功能的长段说明移到 `docs/usage.md`。
2. **`docs/usage.md`** 按功能分章，合并 README 里移出的内容。每章写清楚：怎么用、默认设置、怎么关闭、已知限制。以各任务报告和当前代码的实际行为为准，**不要写没实现的功能**。
3. **`docs/README.md`**：文档索引，分“用户文档”“开发与查证”“任务报告”三类。
4. 新增 **`CHANGELOG.md`**：
   - 按里程碑（M0 / M1 / M2 / M3 / M4 第一步）列出已交付的能力；
   - 引用对应提交；
   - 顶部写 `Unreleased`。

## 第三部分：包信息

1. `packages/host/package.json` 与 `packages/core/package.json` 核对以下字段：
   - `description`；
   - `license: MIT`；
   - `repository`：若用户尚未提供地址，留空并在报告中列为待确认；
   - `files`：只包含 `lib`、`companion`、`cordis.patch.yml` 等运行必需内容，不含测试和源码映射以外的多余文件；
   - `engines`：保持 `node >=22.19` 与 `dsh` 0.2.1-rc.2 或 0.2.1-rc.3。
2. 确认根目录 `LICENSE` 为 MIT，版权人一栏若不确定，列为待确认，不要编造。
3. 用 `pnpm --filter dsh-whaledot pack`（或等价命令）生成本地包，只用于检查内容：列出包内文件清单写进报告，确认没有 `.dsh-dev`、`.dsh-ref`、测试、提示词。检查完删除生成的包，不提交。
