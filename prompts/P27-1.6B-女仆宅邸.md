## 目标

> **实验功能（作者已确定）**：宅邸随 1.6.0 发布，但**默认关闭**。设置 `world.enabled` 默认关；在 **设置 → WhaleMaid** 与“主动性”卡片附近提供“开启宅邸（实验）”开关；开启后面板出现带“实验”标记的“宅邸”标签。“桌宠走进宅邸”同样**默认关闭**，在宅邸设置里单独开启。关闭宅邸后不再渲染、不调用舞台、不影响桌宠，已有显示偏好保留。

在 WhaleMaid 面板新增“宅邸”标签：一座 2.5D 等距、楼层分开的女仆宅邸。**每个目标一个房间，每个任务一件会显示进度的摆件**，房间状态、信件、便签、天色都来自真实记录；大肥鱼由 Coopanion 的舞台绘制，在她所在的房间里走动、坐着干活、睡觉，对你的点击做出表情。世界只负责“看”和“跳转”，不新增任何权限。

## 许可边界（必须遵守）

- **不得**复制、改写或打包 Coopanion 的任何代码、角色贴图、缩略图或动画数据。大肥鱼只能通过舞台协议请 Coopanion 绘制。
- WhaleMaid 一侧只依据 `stage-protocol.md` 实现消息收发；在报告中说明这一点。`pnpm check:license --reference ../dsh-coopanion` 要通过。

## 先查证（写进报告，附出处）

1. 面板客户端现有的标签与路由结构，“宅邸”标签放在哪里；面板不可见时如何得知（停止渲染）。
2. 为“世界快照”需要读取的现有数据：目标、任务、运行状态、验收计数（通过 / 失败）、步骤或检查点、停滞计数、决策通知、建议卡、雷达观察与 D10 状态、暂停 / 撤销 / 全局暂停、已完成目标的总结与经历。哪些数据缺失时摆件显示中性状态。
3. 舞台的嵌入方式按 P26 报告选定的方案接入；确认在 DSH 桌面版与远程浏览器中都能显示，并确认没有兼容 Coopanion 时的检测方式。

## 实现

### 1. core：世界快照（纯函数）

- `buildWorld(facts, now, prefs)`：把记录快照转成房间、摆件、状态标记和角色位置的结构化数据。不读时钟、不做 IO。
- 房间：每个未归档的目标一个；固定房间大厅、厨房、陈列室、卧室。房间大小按任务数分小 / 中 / 大（槽位 4 / 6 / 8），超出时已通过的任务收进“收纳柜”（显示数量）。
- 摆件：按设计文档 3.1 节，水缸（验收通过比例，执行中冒泡，失败变浑）、书架（步骤进度）、盆栽（任务阶段，长期停滞会蔫）、台灯（正在执行）、纪念摆件（已通过）。分配规则：有可计数测试的任务优先用水缸，同一房间尽量不重复。无数据时为中性状态，不臆造进度。
- 房间状态标记：杂乱程度（来自主动性发现与失败）、门上的信（待决定）、软木板便签（建议卡）、玄关包裹 / 灯光闪烁（雷达 D8 / D9）、“请勿打扰”牌（D10 等待中）、窗帘拉上（暂停）、门上锁（授权撤销）、全局暂停（大门关闭）。
- 已完成的目标进陈列室，成为纪念品。
- 大肥鱼的位置与动作：在正在执行的房间里 `sit-work`；多个房间在执行时按固定节奏在它们之间 `walk`；空闲时白天在大厅 `idle`、夜里在卧室 `sleep`；有待决定时偶尔走到那间的门口。
- 时间段：按本机时区分清晨 / 白天 / 傍晚 / 夜晚，勿扰时段进入安静状态（铃铛不晃、信件无动画）。

### 2. 宿主与面板 API

- 新增只读查询 `world`，返回快照（含时间段、房间、摆件、标记、角色指令）。**不写任何业务数据。**
- 配置：`world.enabled`（默认关）、`world.petWalksIn`（默认关）；面板里一键开关，不需要重启。
- 宅邸自己的显示偏好（归档的房间、视角位置、“桌宠走进宅邸”开关）存进 WhaleMaid 的设置记录，不影响目标。归档房间进入“储藏室”列表，可随时搬回。
- “桌宠走进宅邸”（实验，默认关）：标签可见时经宿主调用 Coopanion 的离开控制，不可见或关闭时调用返回；按客户端计数、断线恢复、尊重用户的手动隐藏，这些由 Coopanion 一侧保证，WhaleMaid 只负责成对调用并在 dispose 时返回。

### 3. 客户端渲染

- Canvas 2D 自行做 2:1 等距坐标换算与深度排序，**不引入 3D 引擎**；只有实测性能不足时才考虑 2D 渲染库，需在报告中说明许可与体积。
- **楼层分开**（层间留空隙），一层最多 4 个房间，目标多了往上加楼层；可拖动、缩放，有“回到大肥鱼所在处”按钮。
- **一种房间、做精致**：墙纸、木地板、踢脚线、窗与窗帘、地毯、柔和光影与阴影；摆件是视觉重点，连续进度要能一眼读出（水位、书本数量、植物高度、灯光）。白天 / 傍晚 / 夜晚的天色和灯光平滑过渡，夜里没活的房间变暗、有活的房间亮台灯。
- **小物件**（门上的信、铃铛、便签）：先由程序绘制；同时预留可替换的素材位（例如 `packages/host/world/letter.png`、`bell.png`、`note.png`，存在时按需加载并优先使用，规则同欢迎页图片），方便作者以后换成手绘。
- **大肥鱼**：通过舞台协议显示在场景上层，坐标随视角换算；点击 / 悬停时让她做表情（只是表演）。没有兼容的 Coopanion 时显示作者绘制的比心静止立绘（复用欢迎页的 `dafeiyu-still.png`，按需加载），面板提示“安装完整版可以看到她在宅邸里活动”。
- **交互**：悬停房间显示摘要（目标名、进度、待处理）；点击房间打开目标详情；点击信件 / 便签打开现有决策卡 / 建议卡；点击陈列品打开已完成目标的总结；点击收纳柜显示被收起的任务。所有操作都走现有界面和确认通道。
- **列表视图**：同一份快照的文字版，供读屏、“减少动态效果”以及加载失败时使用。
- **性能**：标签不可见时停止渲染与舞台；没有动画时降到每秒数帧；素材按需加载；在 20 个目标、每个 8 个任务的夹具下保持流畅（报告里给出帧率与 CPU 粗测）。

## 不要做

- 不新增任何操作权限或动作类型；世界里没有奖励、惩罚、养成机制。
- 不做时间回放、不做按目标类型的多种房间、不做桌宠窗口里的小地图。
- 不调用模型。
- **不要推送，不要打标签。**

## 测试

- `buildWorld` 表驱动：每种状态（执行中、失败、反复失败、停滞、待决定、建议卡、雷达 D8 / D9 / D10、暂停、撤销、全局暂停、完成、归档）的房间与摆件输出；摆件分配与槽位溢出；无数据的中性状态。
- 布局：0、1、4、5、20、40 个目标的楼层排布，房间不重叠；归档后重新排布。
- 时间段：各段边界、时区、勿扰安静状态。
- 角色指令：单个 / 多个执行中房间、空闲白天 / 夜晚、待决定时的移动。
- 舞台对接：协议版本不匹配、Coopanion 缺失时的回退；离开 / 返回成对调用，dispose 时返回。
- 默认关闭：未开启时没有“宅邸”标签、不请求 `world` 快照、不加载舞台、不调用离开控制；开启 / 关闭无需重启。
- 交互：每个可点击元素打开正确的现有界面，不产生新的操作路径；列表视图与画面一致；减少动态效果时无动画。
- 全量 `pnpm test`、`pnpm typecheck`、**`pnpm lint`**（含许可检查）、`pnpm format:check`、`pnpm test:package` 通过；`pnpm check:license --reference ../dsh-coopanion` 通过。

## 隔离实测

在隔离环境 `whaledot-p02`（`.dsh-dev`，端口 3182，**不碰日常 profile，不在设了 DSH_HOME 的终端里启动桌面版 Harness**），安装本地打包、内含本地 Coopanion 0.6.0 的完整包：

1. 用若干虚构目标构造：一个执行中（多任务、不同进度）、一个反复失败带建议卡、一个待决定、一个暂停、一个撤销、一个已完成；截图白天与夜晚。
2. 确认默认没有“宅邸”标签；在设置中开启宅邸和“桌宠走进宅邸”后打开标签，确认桌面桌宠跳一下后隐藏、在宅邸里出现并坐在执行中的房间；离开标签后回到桌面；手动隐藏的桌宠不被打开。
3. 点击信件、便签、房间、陈列品，确认打开正确的界面；点击大肥鱼看到表情。
4. 卸载或停用 Coopanion 后确认回退立绘与提示。
5. 远程浏览器访问时（同机另一浏览器即可）宅邸与舞台均正常。
